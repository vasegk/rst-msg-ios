# Записи iOS-клиента для серверной части

Правила те же, что у Android (`rst-msg-android/docs/HANDOFF_README.md`):
этот файл пишет iOS-часть, новые записи сверху, вопросы — в «Открытых вопросах».
Серверная часть этой папки, скорее всего, не видит — владелец переносит записи
в `HANDOFF.md` репозитория `rst-msg`.

---

## 2026-10-05 — первый этап: ядро мессенджера

Создан нативный клиент на SwiftUI (iOS 17+), репозиторий `rst-msg-ios`.
Протокол — по `PROMPT_ANDROID.md`, без отступлений. Сделано: вход и регистрация
с полной схемой ключей (600 000 итераций у новых), автологин, ключ восстановления,
смена пароля, сеансы; список чатов с папками, архивом, закреплением, отключением
уведомлений; переписка в реальном времени (ответы, правка, удаление, пересылка,
реакции, закреп, опросы, голосовые, вложения со сквозным шифрованием, очередь
без связи, догон через `after_id`, черновики через `/api/drafts`); группы
(создание с ключом, раздача `share_key` новичкам, проверка переданного ключа,
правило «ключ из номера — только если настоящего нет ни у кого», ссылка с `#k=`);
профиль, приватность, автоответ, тихие часы.

Совместимость проверена тестами на эталонах WebCrypto (Node.js `crypto.subtle`).

Изменений протокола нет.

## Открытые вопросы

1. **Push на iPhone (APNs).** iOS не держит сокет в фоне и не даёт запустить
   постоянную службу, как Android. Нужен push через APNs. Варианты:
   - через тот же Firebase: в проект Firebase загрузить APNs-ключ (.p8), клиент
     регистрирует FCM-токен как Android (`POST /api/push/fcm/register`).
     Но **data-only сообщения на iOS приходят «тихо» и система их режет** —
     для iOS нужен push с `notification` (хотя бы `{"title":"RST","body":"Новое сообщение"}`)
     и `mutable-content: 1`, чтобы расширение Notification Service на устройстве
     само скачало и расшифровало сообщение по `chat` и `id`. Просьба: поле
     `platform: "ios"` в `fcm/register` и для таких токенов — APNs-блок
     `{"aps":{"alert":{"title":"RST","body":"Новое сообщение"},"mutable-content":1,"sound":"default"}}`
     с теми же `t`, `chat`, `id`, `to` в данных. Текста сообщения в push по-прежнему нет.
   - звонки: VoIP-push (PushKit) — отдельным этапом.
   Нужен платный Apple Developer аккаунт; у владельца он будет позже.
2. **Universal links.** Чтобы ссылки `https://rst-msg.ru/join/…` и `/@ник`
   открывались в приложении, на сервере нужен файл
   `https://rst-msg.ru/.well-known/apple-app-site-association`
   (`applinks` с `appIDs: ["<TEAM_ID>.ru.rstmsg.messenger"]`, пути `/join/*`, `/@*`).
   TEAM_ID появится вместе с аккаунтом разработчика. Пока работает схема `rstmsg://`.
3. **Голосовые из Chrome** приходят `audio/webm` (Opus в WebM) — iOS этот контейнер
   не воспроизводит. Варианты: веб пишет голосовые в `audio/mp4`, где браузер умеет
   (Chrome на Android и десктопе умеет `audio/mp4` не везде), либо iOS перекодирует
   сам (тяжело). Пока показывается «Формат WebM на iPhone не воспроизводится».
