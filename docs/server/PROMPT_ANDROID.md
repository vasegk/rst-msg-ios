## Связь с серверной частью

Над проектом работает второй ассистент — он ведёт сервер и веб-клиент
в репозитории `rst-msg`. Чаты между собой не связаны, поэтому договариваться
приходится через файлы.

Доступ у сторон разный: серверная часть видит обе папки, мобильная — только
свою. Поэтому обмен идёт через файлы в папке Android-проекта:

|---|---|---|

| `docs/HANDOFF_FROM_SERVER.md` | серверная часть | мобильная |

**Правило номер один: перед началом любой задачи сначала прочитайте
`docs/HANDOFF_FROM_SERVER.md`** — первым действием, а не по напоминанию
пользователя. Там ответы серверной части и предупреждения об изменениях,
которые могли сломать ваш код.

**После работы допишите свою запись** в `docs/HANDOFF_ENTRY.md`, новые сверху,
вопросы — в раздел «Открытые вопросы».

Чужой файл не редактируйте: ответы затрутся при следующей записи.

## Сервер

- Базовый адрес задаётся в настройках сборки, боевой домен — `rst-msg.ru`
- Протокол — только HTTPS/WSS
- Формат — JSON, `Content-Type: application/json`
- Авторизация — `Authorization: Bearer <access_token>` (JWT, HS256, срок **30 дней**).
  Продлевать заранее: `POST /api/token/refresh` с действующим токеном → новый
  `{access_token, token_type}`. Протухший или отозванный токен не продлевается —
  только новый вход.
- Ошибки — код HTTP плюс тело `{"detail": "текст"}`; при 429 есть заголовок `Retry-After`.
  При 422 (не прошла проверка полей) `detail` — массив объектов
  `{loc, msg, type}`, а не строка: берите `loc` последним элементом как имя поля.

Бэкенд: Python, FastAPI, PostgreSQL. Сообщения хранятся зашифрованными, ключей
расшифровки у сервера нет.

## Криптография — читать внимательно

Это самая ответственная часть. Любое расхождение с описанным ниже приведёт
к тому, что приложение не расшифрует сообщения, отправленные из браузера,
и наоборот. Всё делается на устройстве, ключи на сервер в открытом виде
не уходят никогда.

### Регистрация

1. `POST /api/register` с `{username, password, email, kdf_iterations}`.
   В ответе приходят `kdf_salt` — случайная строка из 32 hex-символов — и
   `kdf_iterations`. Новые клиенты передают `kdf_iterations: 600000`;
   без поля сервер запишет 100 000 (прежнее значение).
2. Сгенерировать пару **ECDH P-256**.
3. Экспортировать обе части в **JWK** и сериализовать в JSON-строку.
4. Вывести ключ шифрования ключа (KEK) из пароля:
   **PBKDF2-HMAC-SHA256, число итераций — `kdf_iterations` из ответа,
   соль — `kdf_salt` в виде UTF-8 байт, длина результата 256 бит.**
5. Зашифровать JSON приватного ключа алгоритмом **AES-GCM** с этим KEK,
   вектор инициализации — 12 случайных байт.
6. Результат упаковать в строку:
   `{"iv":"<base64 IV>","ciphertext":"<base64 шифротекста>"}`
7. Войти (см. ниже), затем `POST /api/keys/upload` с
   `{username, public_key, encrypted_private_key}`, где `public_key` —
   JSON-строка публичного JWK.

### Вход

1. `POST /api/login` с `{username, password}`.
   Поле `username` принимает и имя, и email.
2. Из ответа сохранить: `access_token`, `username`, `original_username`, `kdf_salt`,
   `kdf_iterations`.
3. Заново вывести KEK из пароля и `kdf_salt` **с числом итераций из
   `kdf_iterations`**. ЛОМАЕТ СОВМЕСТИМОСТЬ: аккаунты, созданные в вебе после
   2026-09-15, используют 600 000 итераций. Клиент, зашивший 100 000, не
   расшифрует их приватный ключ. Старые аккаунты по-прежнему приходят с
   `kdf_iterations: 100000`.
   **KEK хранить только в защищённом хранилище устройства** (EncryptedSharedPreferences
   или Android Keystore), не в обычных настройках.
4. `GET /api/keys/{username}` — вернёт `encrypted_private_key` (только для себя).
   Расшифровать его KEK-ом, получить JWK приватного ключа, импортировать.

Пароль на сервере хранится хешем bcrypt и никогда не передаётся никуда,
кроме `/api/login` и `/api/register`.

### Ключ переписки

**Личный чат:** ECDH между своим приватным ключом и публичным ключом
собеседника (`GET /api/keys/{username}` → поле `public_key`), результат —
ключ **AES-GCM 256**.

**Группа:** у группы есть случайный ключ AES-256. Для каждого участника он
зашифрован отдельно и лежит в его строке `group_members.encrypted_key`.

Получение ключа группы:

1. `GET /api/groups/{group_id}/key/{моё_имя}` → `{encrypted_key}`
2. Если `encrypted_key` непустой — разобрать JSON:
   `{"v":1,"by":"<кто упаковал>","iv":"<base64>","ciphertext":"<base64>"}`
3. Получить публичный ключ пользователя `by` (`GET /api/keys/{by}`)
4. Вывести ключ распаковки: ECDH между своим приватным и его публичным
   (ECDH симметричен, поэтому подходит ключ любого из двоих)
5. Расшифровать `ciphertext` алгоритмом AES-GCM — получатся 32 байта
   ключа группы, импортировать как AES-GCM

Упаковка ключа для нового участника — та же операция в обратную сторону:
ECDH со своим приватным и его публичным ключом, AES-GCM, поле `by` — своё имя.

**Старые группы и запасной ключ.** Группы, созданные до перехода на эту схему,
не имеют `encrypted_key`. Для них (и для сообщений, отправленных в любой группе
до перехода) ключ вычисляется прежним способом:
`SHA-256(UTF-8("group_<id>_rst_group_salt"))` → 32 байта → AES-GCM.

Порядок при расшифровке группового сообщения: сначала настоящий ключ,
при неудаче — прежний. Шифровать всегда настоящим, если он есть.

> Прежняя схема небезопасна: номер группы известен серверу, значит сервер
> может вывести ключ. Поддерживать её нужно только ради читаемости старой
> переписки. В интерфейсе такие группы помечены предупреждением — сделайте
> так же.

**Писать ключом из номера группы — только если настоящего ключа нет ни у кого
(с 2026-09-27, обязательно).** Раньше клиент откатывался на прежний ключ при
любом ответе «ключа нет» (404), и сервер мог этим снять шифрование с любой
группы. Правило:
- запоминайте на устройстве группы, где у вас хоть раз был настоящий ключ;
- если своего ключа нет, смотрите `GET /api/groups/{id}/info` → `members[].has_key`;
- группа запомнена ИЛИ у кого-то `has_key: true` (ИЛИ сведения не загрузились) —
  **не отправляйте**: покажите «ключ группы ещё не пришёл», ждите
  `group_key_shared`. Читать старое прежним ключом можно;
- иначе (настоящего ключа нет ни у кого) — прежняя схема с предупреждением.
Администратор старой группы может включить шифрование: новый случайный ключ,
своя копия — `POST /api/groups/set_my_key`, остальным — `POST /api/groups/share_key`
(пишется только в пустую копию).

**Код безопасности (с 2026-09-27, желательно — чтобы коды совпадали с вебом).**
Сверка ключей собеседников от подмены сервером. Строка ключа —
`crv|x|y` из JWK. Свой ключ берите из расшифрованного закрытого (поля
`x`, `y`), не с сервера. Две строки сортируются, код —
`SHA-256(UTF-8("rst-safety-v1|" + a + "|" + b))`, из первых 24 байт — 12
групп: `((b[2i] << 8) | b[2i+1]) % 100000`, дополнить нулями до 5 цифр.
Запоминайте отпечаток открытого ключа каждого собеседника; сменился —
предупредите в переписке.

**Вступление по ссылке.** Ссылка-приглашение выглядит как
`https://домен/join/<invite_hash>#k=<base64 ключа группы>`.
Часть после `#` — фрагмент, браузером на сервер не отправляется, поэтому ключ
через сервер не проходит. Приложение должно разобрать этот фрагмент при
открытии ссылки, вступить в группу, затем упаковать ключ для себя
(ECDH со своим же публичным ключом) и сохранить:
`POST /api/groups/set_my_key {group_id, encrypted_key}`.

**Публичные группы и короткие ссылки.** При вступлении через `join_public`
или по короткой ссылке `rst-msg.ru/имя` ключа взять неоткуда — фрагмента с
ключом там нет. С 2026-09-16 ключ передаёт кто-то из участников, у кого он
есть: в `/api/groups/{id}/info` у каждого участника появилось поле
`has_key`, и клиент, у которого ключ есть, упаковывает его для тех, у кого
нет, через `POST /api/groups/share_key {group_id, username, encrypted_key}`
(тот же формат пакета, что и везде). Сервер принимает копию, только пока
она пуста, и отвечает `{"status":"already_has_key"}`, если ключ уже есть.

Получателю приходит `{"action":"group_key_shared","group_id","by"}` — по
нему нужно перечитать ключ группы и перерисовать чат. Ключ стоит проверить
делом: расшифровать пару последних сообщений группы и, если не вышло,
остаться на прежнем ключе (участник мог передать негодный пакет).

Пока ключа нет, группа читается прежним ключом, выводимым из её номера, —
сквозного шифрования в ней нет, и это по-прежнему нужно показывать.

### Шифрование сообщения

Текст шифруется ключом переписки, AES-GCM, IV — 12 случайных байт, и
упаковывается в ту же строку `{"iv":"...","ciphertext":"..."}` (base64).
Именно эта строка кладётся в поле `content`.

### Конверт для вложений

Когда к сообщению приложен файл, вместо простого текста в `content`
шифруется JSON следующего вида:

```json
{"__rst":1,"t":"подпись","k":"<base64 ключа файла>","n":"имя файла","m":"image/png"}
```

При расшифровке: если результат — строка, начинающаяся с `{`, и после
разбора это объект с полем `__rst == 1`, то `t` — текст сообщения,
`k` — ключ вложения, `n` — имя, `m` — MIME-тип, `a` — номер альбома (с
2026-10-07, см. «Альбомы»). Иначе перед вами обычное текстовое сообщение
(старый формат, поддерживать обязательно).

### Шифрование файла

1. Сгенерировать случайный ключ **AES-GCM 256** — свой для каждого файла.
2. Зашифровать содержимое файла: 12 случайных байт IV, затем шифротекст.
3. Отправить как **единый бинарный поток: 12 байт IV + шифротекст**.
4. `POST /api/upload`, `multipart/form-data`, имя поля `file`,
   имя файла — `attachment.enc`.
5. Ключ (base64 сырых байт) положить в поле `k` конверта, MIME-тип — в `m`.
   В `file_type` сообщения отправить `application/octet-stream`.

При получении: скачать файл по `file_url`, отделить первые 12 байт как IV,
расшифровать остальное ключом из конверта.

Свой ключ у каждого файла нужен для пересылки: при пересылке в другой чат
файл не перезаливается, в новый конверт кладётся тот же ключ `k`.

**Аватары не шифруются** — их видят люди, с которыми общего ключа нет.
Они загружаются обычным `POST /api/upload` как есть.

### Опросы

Вопрос и варианты шифруются как обычное сообщение — в том же конверте:

```json
{"__rst":1,"t":"📊 Вопрос","p":{"q":"Вопрос","o":["Вариант 1","Вариант 2"]}}
```

Отправка: `send` с `file_type: "application/x-rst-poll"`, без `file_url`, и
`"poll": {"options": <число вариантов 2..10>, "multiple": false, "anonymous": true}`.
Отложить опрос нельзя, изменить после отправки — тоже. Серверу известно только
число вариантов и кто за какой номер голосовал.

Клиент, не знающий об опросах, покажет поле `t` («📊 Вопрос») как обычный текст —
поэтому неизвестные поля конверта нужно игнорировать, а не падать.

Состояние (`poll` в истории и в `new_msg`, в `poll_update`):
`{options, multiple, anonymous, closed, counts:[..], voters, my:[..]}`;
в открытом опросе ещё `voters_by_option:[[имена]..]`. `my` — ваш выбор: в
истории он есть всегда, в `poll_update` приходит только вашим устройствам.
Голос — `poll_vote` с `options` (пустой список отменяет голос), завершить может
автор — `poll_close`. Результаты показывать после своего голоса или завершения.

### Разметка текста сообщения

Разметка — часть расшифрованного текста; сервер её не видит и не трогает.
Разбирает получатель. Эталон — `js/text-format.js` (`renderMessageText`,
`stripFormatting`) и его тесты `tests/js/text-format.test.mjs`.

| Запись | Вид |
|---|---|
| `**текст**` | жирный |
| `__текст__` | курсив |
| `++текст++` | подчёркнутый (с 2026-09-25) |
| `~~текст~~` | зачёркнутый |
| `\|\|текст\|\|` | спойлер: скрыт до нажатия |
| `` `код` ``, ```` ```блок``` ```` | моноширинный; внутри разметка не действует |
| `> ` в начале строки | цитата; подряд идущие строки — один блок |
| `[слова](https://адрес)` | ссылка под словами (с 2026-09-25) |

Правила: пробел сразу внутри маркера отменяет стиль (`2 ** 3 ** 4` — не
жирный). Ссылка под словами — только `http://` и `https://`; адрес без
пробелов и скобок `()<>`. Если слова ссылки не совпадают с адресом, веб перед
открытием спрашивает «Открыть ссылку?» с настоящим адресом — сделайте так же,
иначе под словами «сбербанк.ру» может прийти любой адрес. В превью (список
чатов, ответ, уведомление) разметка снимается: ссылка — остаются слова,
спойлер — `▒▒▒▒`.

## REST API

Все требуют `Authorization: Bearer`, кроме `/api/register` и `/api/login`.

### Учётная запись
- `POST /api/register` → `{message, kdf_salt, kdf_iterations}`
  Пароль: **минимум 8 символов, максимум 72 байта**. Имя: `^[a-zA-Z0-9_-]{3,32}$`.
  Ограничение: 5 регистраций в час с одного адреса.
- `POST /api/login` → `{username, original_username, kdf_salt, kdf_iterations, access_token, token_type}`
  Ограничение: 10 попыток за 5 минут, затем блокировка на 15 минут.
- `POST /api/keys/upload` `{username, public_key, encrypted_private_key}`
- `GET /api/keys/{username}` → `{public_key, encrypted_private_key}`
  (приватный ключ приходит только когда запрашиваешь сам себя)
- `POST /api/profile/update` — `display_name`, `bio`, `status`, `avatar_url`,
  `birthday`, `birthday_privacy`, `phone_privacy`, `email_privacy`,
  `last_seen_privacy`, `email`, `phone`. Применяются только переданные поля.
  `avatar_url` принимается только в формате `/uploads/<32 hex>.<png|jpg|jpeg|gif|webp>`.
  С 2026-09-16 значения проверяются, иначе 422: `status` — `online|dnd|offline`;
  все `*_privacy` — `everyone|contacts|nobody` (`contacts` — «мои контакты»,
  с 2026-09-26: поле видят только те, кому владелец сам писал в личку; кто
  написал первым, увидит его после ответа владельца); `birthday` — `ГГГГ-ММ-ДД` или пусто;
  `phone` — до 32 символов из цифр, пробелов и `+ ( ) - .`; `email` — с одной `@`,
  без пробелов и `< >`; `display_name` (до 64) и `bio` (до 200) — без `< >`.
  С 2026-09-29 ещё три поля (видны только самому человеку — в своей записи
  списка контактов):
  `call_privacy` — кто может звонить (`everyone|contacts|nobody`, по умолчанию
  `everyone`); `group_invite_privacy` — кто может добавлять в группы (так же);
  `story_comments` — `true|false`, принимать ли комментарии к своим историям
  (по умолчанию `true`).
  Ещё три (с 2026-09-29, в своей записи списка контактов — `default_timer` и
  `quiet_hours`):
  `default_timer` — автоудаление, которое само включается в новых чатах: `0`,
  `86400`, `604800` или `2592000` (иначе 422). Сервер ставит его при первом
  сообщении в личку, где между двумя людьми ещё не было ни одного сообщения
  (обоим приходит `chat_timer` от отправителя — раньше, чем `new_msg`), и при
  создании группы. `quiet_hours` — `"ЧЧ:ММ-ЧЧ:ММ"` (может переходить через
  полночь) или `""` — выключено; `time_zone` — пояс IANA (`Europe/Moscow`),
  присылайте его вместе с `quiet_hours`. В тихие часы push о сообщениях не
  отправляется; о звонках — отправляется. Звук и уведомления в открытом
  приложении в эти часы тоже стоит глушить.
  С 2026-09-30 ещё два (в своей записи списка контактов, по умолчанию `true`):
  `notify_private` и `notify_groups` — уведомления из личных чатов и из групп.
  Выключенное сервер не будит push; приложение тоже молчит (без звука и
  всплывающего окна), но непрочитанные считает. Упоминание в группе сильнее
  выключенного — как и с заглушённым чатом. Общие для всех устройств.
- `POST /api/users/change_password` `{old_password, new_password, kdf_salt,
  kdf_iterations, encrypted_private_key, current_device}` — приватный ключ
  перешифровывает клиент: новая соль (32 hex), новый KEK, тот же JWK.
  → `{status, kdf_salt, kdf_iterations, access_token}`. Остальные устройства
  получают по сокету `{"action":"force_logout"}` и закрытие с кодом 4001.
- Ключ восстановления (с 2026-09-29) — новый пароль без потери переписки.
  Код генерирует клиент: 20 случайных байт в алфавите `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`
  (32 знака, показываются группами по 4 через «-»). Нормализация: верхний регистр,
  без пробелов и «-». Из нормализованного кода — PBKDF2-SHA256, соль — `recovery_salt`
  (строка 32 hex, как есть в UTF-8), 100 000 итераций, 512 бит: первые 32 байта — ключ
  AES-GCM, которым шифруется **тот же JWK приватного ключа** (формат `{"iv","ciphertext"}`,
  как `encrypted_private_key`); вторые 32 байта в hex — `recovery_auth`. Код и первая
  половина на сервер не уходят.
  - `GET /api/recovery/status` → `{enabled, created_at}`.
  - `POST /api/recovery/setup` `{password, recovery_salt, recovery_key, recovery_auth}` —
    создать/заменить (нужен пароль; неверный — 400).
  - `POST /api/recovery/begin` `{username}` (имя или почта) → `{recovery_salt, kdf_iterations}`;
    404 — у аккаунта нет ключа.
  - `POST /api/recovery/unlock` `{username, recovery_auth}` → `{recovery_key, username}`;
    400 — не тот ключ. Попытки считаются вместе со входом.
  - `POST /api/recovery/reset` `{username, recovery_auth, new_password, kdf_salt,
    kdf_iterations, encrypted_private_key}` — приватный ключ, перешифрованный под новый
    пароль. → `{access_token, username, original_username, kdf_salt, kdf_iterations}`;
    все прежние сеансы отзываются (`force_logout`). Ключ восстановления остаётся прежним.
- `GET /api/users/blocked` → `{"blocked":[{"username","name","avatar_url"}]}`
- `POST /api/users/delete_account` `{password}` — с 2026-09-27 только с паролем
  (ЛОМАЕТ старый вызов без тела: 422). Неверный пароль — 400; попытки
  считаются вместе со входом.
- `GET /api/sessions/{username}` → `{"sessions":[{"device_id":"dev_abc","ip":"1.2.3.4","ua":"..."}]}`
  Список строится из активных соединений WebSocket в памяти сервера:
  после перезапуска службы он пуст, пока клиенты не переподключатся.
- `POST /api/sessions/terminate` `{username, current_device}` → `{status, closed, access_token}`.
  Все прежние токены отзываются (растёт `token_version`), текущее устройство
  получает новый токен — сохраните его. Другие устройства получают
  `{"action":"force_logout"}`.

### Контакты
- `GET /api/contacts/{username}` → `{users, groups}` — список чатов.
  Точные поля (имена важны, они не такие, как можно ожидать):
  ```json
  {
    "users": [{"username":"ivan","name":"Иван","avatar_url":"/uploads/x.png",
               "bio":"","birthday":"","birthday_privacy":"everyone",
               "email":null,"phone":null,
               "online":true,"status":"online","unread":3}],
    "groups": [{"id":"group_2","name":"Проект","avatar_url":null,"unread":0,
                "admins_only":false,"slow_mode":0,"my_role":"member"}]
  }
  ```
  У обоих видов есть также `muted`, `pinned`, `archived`, `marked_unread`
  (настройки чата), `last_msg` `{id, sender, content, file_type, time, status}` —
  `content` зашифрован; `status` (с 2026-09-29) — `sent|read`, для галочек у своего
  последнего сообщения — в личке и в группе; у пользователей — `last_seen` (скрыт, если человек
  так настроил) и `is_system` (аккаунт поддержки `support`, писать в него нельзя).
  `unread` — только чужие сообщения после отметки прочтения (с 2026-10-07 и в
  группах). В личке (с 2026-10-07) не считаются удалённые «у себя» и истёкшие по
  таймеру, а кадр `read` с `message_id` N отмечает прочитанными все сообщения
  собеседника с id <= N, как в Telegram: достаточно слать `read` для последнего
  увиденного. Общий счётчик (значок приложения) архивные чаты не включает — у строки
  «Архив» свой серый счётчик.
- `POST /api/chats/prefs` `{chat_id, muted?, mute_for?, pinned?, archived?, marked_unread?}`
  → итоговые `{muted, muted_until, pinned, archived, marked_unread}`. Уход в архив
  снимает закрепление. `marked_unread` снимайте, когда человек открывает чат.
  `mute_for` — отключить уведомления на столько секунд (0 — включить, -1 —
  навсегда); `muted_until` — ISO с `Z` или `null` (навсегда). В `/api/contacts`
  истёкшее отключение уже приходит как `muted: false`.
  `name` уже содержит заданное вами имя контакта, отдельного поля нет.
  `email` и `phone` непустые только для себя. У групп `id`, а не `group_id`;
  `is_public` и `role` приходят из `/api/groups/{id}/info`.
- `GET /api/users/search?q=` → `{users}` (email и телефон не отдаются).
  **С 2026-10-02 — только `q`, начинающийся с «@»**: `@vix` → все, чей ник
  начинается на `vix` (без учёта регистра), точный ник первым, не более 20.
  Без «@» ответ всегда пустой; имя и середина ника не ищутся — так закрыт
  перебор базы по одной букве. Свои чаты и контакты ищите на устройстве (по
  имени тоже), открытие профиля по ссылке — запросом `@ник`.
  Ниже - прежнее описание, верное до 2026-10-02:
  С 2026-09-16 поиск не зависит от регистра (в том числе для кириллицы),
  пробелы по краям отбрасываются, а результаты идут по совпадению: сначала
  точное имя или ник, затем начинающиеся с запроса, затем остальные; не
  более 20. Пустой запрос - пустой ответ. Удалённые аккаунты не выдаются.
  Поиск ищет по нику и отображаемому имени; заданное вами имя контакта
  сервер не знает - по нему ищите у себя, как это делает веб.
- `POST /api/contacts/rename` `{owner, target, custom_name}`
- `POST /api/users/block` / `POST /api/users/unblock` `{blocker, blocked}`
- `GET /api/users/{username}/shared/{target}` → `{shared_groups, is_blocked}`
- `POST /api/users/report` `{reporter, reported, reason}`

### Сообщения
- `GET /api/messages/{user1}/{user2}?limit=200&before_id=<id>&after_id=<id>`
  → `{messages, has_more, oldest_id}`
  `user1` — всегда вы, `user2` — собеседник или `group_<id>`.
  Отдаются последние `limit` (по умолчанию 200, максимум 500) в хронологическом
  порядке. Для подгрузки истории вверх передавать `before_id` = `oldest_id`.

  **`after_id` — догнать пропущенное после перерыва в связи.** Отдаются
  сообщения новее указанного, и это единственный случай, когда выдача
  идёт от старых к новым: при долгом перерыве нужны самые ранние из
  пропущенных, иначе в середине останется дыра. `has_more` здесь значит
  «ниже есть ещё» — повторяйте с последним полученным `id`, пока не
  станет `false`. Так дешевле и правильнее, чем перечитывать переписку
  целиком: место чтения у человека остаётся на месте.
  Поля сообщения: `id, sender, content, file_url, file_type, status, reactions,
  is_edited, reply_to, reply_to_sender, reply_to_content, is_pinned,
  forwarded_from, created_at`, у опросов ещё `poll` (см. «Опросы»).
  Системные сообщения групп: `sender: "system"`, `file_type: "system"`,
  `content` — открытый текст.
  **`content` и `reply_to_content` приходят зашифрованными** — расшифровывать оба.
  `status` принимает ровно два значения: `sent` и `read`. В группах статус
  сообщения не меняется: прочтение там хранится как `last_read_msg_id`.
- `GET /api/messages/{user1}/{user2}/pinned` → `{messages}` — все закреплённые
  сообщения чата без ограничения по количеству. Отдельный запрос нужен потому,
  что основная выдача постраничная и закреплённое может оказаться за её
  границей. Поля: `id, sender, content, file_url, file_type, created_at`.
- `GET /api/messages/{user1}/{user2}/pin_events` → `{events}` — пометки
  «Имя закрепил(а) «текст»» для ленты (с 2026-09-26). Поля: `id, message_id,
  actor` (кто закрепил), `after_id` (пометка стоит сразу после сообщения с
  этим номером), `created_at`, а также `sender, content, file_type`
  закреплённого сообщения — `content` зашифрован, как в самом сообщении,
  текст пометки берётся из него. Последние 300, по возрастанию. Сообщение
  удалено (совсем или для смотрящего) — его пометок в выдаче нет.
- `POST /api/messages/clear_chat` `{user1, user2, mode}` — `mode`: `both` или `me`
- `GET /api/messages/{user1}/{user2}/media` → `{media:[{id, sender, content, file_url,
  file_type, created_at}]}` — последние 200 вложений; `content` зашифрован
  (ключ файла внутри). В группе — только участникам.
- `GET /api/groups/{group_id}/messages/{msg_id}/readers` → `{readers:[{username,
  name, avatar_url, deleted}], total}` — кто прочитал своё сообщение в группе
  до 100 участников.
- Отложенные: `GET /api/scheduled?chat=` → `{scheduled:[{id, receiver, content,
  file_url, file_type, send_at}]}` (`send_at` — ISO с `Z`);
  `DELETE /api/scheduled/{id}`; `POST /api/scheduled/{id}/send_now`.
- Автоудаление: `GET /api/chats/timer?chat=<собеседник|group_N>` →
  `{seconds, set_by}`; 0 — выключено.
- `POST /api/upload` — multipart, поле `file`. **Максимум 25 МБ, и лимит
  считается по передаваемому файлу**, то есть уже по шифротексту: исходный
  файл должен быть не больше `лимит - 28` байт (12 байт вектора инициализации
  плюс 16 байт тега). Ограничивайте выбор заранее.
  Число не зашивайте: запрашивайте `GET /api/limits` при запуске.
  Не больше 60 загрузок за 10 минут на аккаунт, иначе `429` с `Retry-After`.
  Если на сервере кончается место — `507`.
  При превышении сервер отвечает `413` с текстом в `detail`; если файл больше
  `client_max_body_size` в nginx, ту же `413` вернёт сам nginx, но телом будет
  HTML-страница, а не JSON — обрабатывайте по коду ответа.
- `GET /api/limits` → `{max_upload_bytes, max_plain_file_bytes, min_password_length}`
  Авторизации не требует.
  Разрешённые расширения: `.enc` (вложения), `.png .jpg .jpeg .gif .webp
  .mp3 .mp4 .pdf .zip .txt .csv .doc .docx .webm .ogg .wav` (аватары).
  → `{file_url, file_type}`

  `encrypted_keys` — словарь `{"<имя участника>": "<строка пакета ключа>"}`,
  где пакет — JSON `{"v":1,"by":"<кто упаковал>","iv":"...","ciphertext":"..."}`
- `GET /api/groups/{group_id}/info` → `{group_id, name, avatar_url, description,
  members, is_public, invite_hash, alias, admins_only, slow_mode}`; у участника есть `role`
- `POST /api/groups/update` `{group_id, name, description, avatar_url}`
- `POST /api/groups/add_members` `{group_id, members, encrypted_keys}`
  С 2026-09-29 и `create`, и `add_members` молча пропускают тех, кто запретил
  добавлять себя в группы (`group_invite_privacy`: `nobody`, или `contacts`, а
  добавляющему человек сам не писал); сколько пропущено — поле `skipped` в ответе.
- `POST /api/groups/leave` `{group_id}` / `kick` / `ban` `{group_id, target_username}` /
  `promote` `{group_id, target_username, role}` / `delete` `{group_id}`.
  Цель `kick` и `promote` должна быть участником, иначе 404. Администратор не
  меняет роль другого администратора (403). `ban` заранее — только существующего
  пользователя.
- `GET /api/groups/{group_id}/bans` → `{bans:[{username, name, avatar_url}]}`,
  `POST /api/groups/unban` `{group_id, target_username}` — владелец и администраторы.
  Добавление человека через `add_members` снимает с него бан.
- `POST /api/groups/settings` `{group_id, is_public, regenerate_invite, alias,
  description, admins_only, slow_mode}` — всё необязательно.
  `admins_only: true` — писать могут только `owner`, `admin`, `editor`; остальным
  сервер отвечает `error` на `send`. `slow_mode` — секунды из набора
  `0, 10, 30, 60, 300, 900, 3600`: участник (не модератор) пишет не чаще раза
  в столько секунд. Смена режима рассылает участникам `group_settings`.
- `GET /api/groups/search?q=` → `{"groups":[{"id":"group_2","name":"Проект","avatar_url":"/uploads/x.png"}]}`
  Только публичные группы, поиск от двух символов (после обрезки пробелов),
  без учёта регистра, не более 20 результатов; сначала названия, начинающиеся
  с запроса.
  `avatar_url` может быть `null`. Состав участников и роли до вступления
  не показываются.
- `POST /api/groups/join_public` `{group_id}`
- `GET /api/groups/join/{invite_hash}` → `{group_id}`
- `GET /api/groups/{group_id}/key/{username}` → `{encrypted_key}`
- `POST /api/groups/set_my_key` `{group_id, encrypted_key}` — сохранить свою
  копию ключа группы (при вступлении по ссылке)

Роли: `owner`, `admin`, `editor`, `helper`, `member`. Права проверяются на сервере.
Создание групп и `add_members` — вместе не больше 20 за час на аккаунт, жалобы —
не больше 10 за час (429 с `Retry-After`).
Удалять чужие сообщения у всех: владелец — любые, администратор — кроме
владельца, хелпер — участников и редакторов. Закреплять в группе —
`owner`, `admin`, `editor`, `helper`.

### Галочки прочтения в группах (с 2026-09-29)

Своё сообщение в группе — «прочитано» (`status: "read"` в истории и в `last_msg`),
если его прочитал хоть один участник: номер последнего прочитанного у участника
(`read` по сокету с `sender: "group_N"`) не меньше номера сообщения. Выключившие
«Прочитал(а)» не учитываются — ни в галочках, ни в списке прочитавших (`/readers`).
Авторам только что прочитанных сообщений приходит
`{"action":"group_read","group":"group_N","reader":"<кто>","up_to":<номер>}` —
все свои сообщения этой группы с номером `≤ up_to` отметьте прочитанными.

### Истории (с 2026-09-29)

Фото или видео с подписью, видны сутки. Показываются «моим контактам» — тем,
кому автор писал сам в личку (то же, что `contacts` в настройках приватности).

**Шифрование** — как ключ группы, только на одну историю:

1. Файл шифруется как вложение (свой случайный AES-256-GCM ключ, `IV(12) + шифротекст`)
   и загружается через `POST /api/upload` с именем `*.enc`.
2. Случайный ключ истории (AES-256, 32 байта). Им шифруется конверт
   `{"f":"<ключ файла base64>","m":"<MIME>","c":"<подпись, до 200 символов>"}` —
   тем же форматом, что текст сообщения: `{"iv":..,"ciphertext":..}`.
3. Ключ истории упаковывается для каждого зрителя **и для себя** — ровно как
   ключ группы: `{"v":1,"by":"<автор>","iv":..,"ciphertext":..}`, ключ упаковки —
   ECDH(свой приватный, открытый зрителя). Для себя — со своим же открытым ключом.

При открытии: `by` **обязан совпадать с автором** истории, иначе не открывать —
иначе сервер мог бы подложить ключ, упакованный подставным аккаунтом. Распаковать
ключом ECDH(свой приватный, открытый автора), расшифровать конверт, скачать файл
по `file_url` и расшифровать ключом `f`.

    минуту (429), не больше 500 под историей.
  - `DELETE /api/stories/{id}/comments/{comment_id}` — свой комментарий или любой под
    своей историей.
  В ленте у каждой истории — `comments` (число).
  У автора в ленте — `comments_enabled` (с 2026-09-29): `false`, если он выключил
  комментарии (`story_comments`); тогда `POST .../comments` отвечает 403, а поле ввода
  лучше не показывать. Уже написанные комментарии по-прежнему отдаются.
- Скрыть истории (с 2026-09-29): `GET /api/stories/hidden` → `{"hidden":["ivan", ...]}`;
  `PUT /api/stories/hidden` `{"usernames":[...]}` — заменяет список целиком. Скрытые
  не попадают в `audience`, упаковать им ключ нельзя (403), а уже выложенные истории у
  них пропадают сразу: сервер удаляет их ключи и шлёт им `story_deleted` с `id: 0` —
  по нему перезапросите ленту.

Личный ответ на историю (веб: «✉️ Лично» в панели комментариев) — обычное личное
сообщение автору (с 2026-09-29): в конверте
рядом с текстом лежит ссылка на историю
`{"__rst":1,"t":"<текст ответа>","s":{"a":"<автор>","id":<номер>,"th":"<миниатюра>"}}`.
`th` — необязательная миниатюра `data:image/jpeg;base64,...` (до 128 точек по большей
стороне, до 24 000 символов); шифруется вместе с сообщением, поэтому видна и после
того, как история исчезнет. Веб рисует над текстом цитату «История · автор» (у автора —
«Ваша история»), по нажатию открывает историю, если она ещё жива. Приложение, которое
поле `s` не знает, покажет просто текст `t`. Проверяйте `th` перед показом: только
`data:image/(jpeg|png|webp);base64,`.

### Галочка подтверждения и трек в профиле (с 2026-10-02)

**Галочка.** Поле `verified: true|false` у пользователя — в `/api/contacts/{me}`
(и в своей записи, и в чужих), в `/api/users/search` и у участников в
`/api/groups/{id}/info` (`members[].verified`). Ставит только администратор
(`rst admin verify <ник>` / `unverify`); через `/api/profile/update` поле не
меняется — его там молча отбрасывают. Веб рисует синюю галочку (#3897f0) у имени:
список чатов, шапка чата, профиль, состав группы, имя отправителя в группе.

**Трек.** `music_url` и `music_title` — в тех же местах, что `verified`, кроме
состава группы; пустая строка — трека нет. Задаётся так:
1. `POST /api/upload` с файлом `.mp3|.m4a|.aac|.ogg|.wav|.webm` (не шифруется —
   как аватар, его слышат все, кто видит профиль; `.m4a` и `.aac` разрешены с
   2026-10-02) → `{file_url}`;
2. `POST /api/profile/update` `{username, music_url: file_url, music_title}`.
`music_url` принимается только вида `/uploads/<32 hex>.<mp3|m4a|aac|ogg|wav|webm>`,
иначе 422; `music_title` — до 100 символов, без `<` и `>`. `music_url: ""` убирает
трек, и название сервер очищает сам. Событие `profile_update` по сокету теперь
несёт `music_url` и `music_title`. Предел файла — общий, 25 МБ.

### Push в Android-приложение — FCM (с 2026-10-02)

Сервер будит телефон data-сообщением Firebase, когда у **этого устройства** нет
открытого сокета (а не у человека вообще: при открытом вебе телефон всё равно
будится). Текста в push нет — только вид события; приложение само дочитывает
новое по сокету (`after_id`) и показывает уведомление.

* `POST /api/push/fcm/register` `{token, device_id}` → `{status, enabled}`.
  `device_id` — тот же, что в адресе сокета `/ws/{ник}/{device_id}`: по нему
  сервер понимает, на связи ли телефон. Вызывать при входе и при каждом новом
  токене (`onNewToken`). На одном устройстве хранится один токен; токен,
  которым пользовался другой аккаунт, переезжает к текущему. `enabled: false` —
  на сервере нет ключа Firebase, push не придут (служба остаётся запасной).
* `POST /api/push/fcm/unregister` `{token}` — при выходе с устройства.
* Сервер сам забывает токены: удаление аккаунта; «завершить другие сеансы» и
  смена пароля — все, кроме `current_device`; ответ Firebase «токена нет».
* Данные (все значения — строки), приоритет HIGH:
  - сообщение: `{"t":"msg","chat":"<чат с точки зрения получателя: ник или group_N>","id":"<номер>"}`,
    срок жизни сутки; не шлётся для `silent`, заглушённых чатов, в тихие часы
    и при выключенных «Личные чаты»/«Группы» — те же правила, что у web-push;
  - звонок: `{"t":"call","from":"<ник>","video":"1|0"}` по `call_invite`,
    срок жизни 30 с.

### Присутствие «в сети» (с 2026-10-04)

«В сети» теперь значит «смотрит на экран хотя бы одного устройства», а не
«открыт сокет». Иначе свёрнутое приложение со службой и вкладка в фоне держали
человека в сети часами.
* Подключение фоновое — `/ws/{ник}/{устройство}?active=0` (служба, свёрнутое
  приложение): сообщения доставляются, но «в сети» человека не делает и время
  «был в сети» не трогает. Без параметра — активное, как раньше.
* Смена состояния по сокету: `{"action":"presence","active":true|false}` —
  приложение вышло на экран / ушло в фон (веб: вкладка скрыта дольше 20 с или
  5 мин без действий). Повторы того же значения безвредны.
* Событие `presence` (`online`, `last_seen`) рассылается, когда меняется
  итоговое состояние человека, а не каждого сокета.
* Статус «Не в сети» (невидимка): присутствие не объявляется вовсе, `online` в
  `/api/contacts` и поиске — `false`; сам невидимка чужое присутствие видит.
  Смена статуса через `/api/profile/update` сразу рассылает `presence`.

### Цитаты, «прослушано», подписи в группе, викторины (с 2026-10-04)

* **Ответ цитатой.** В конверте сообщения-ответа поле `q` — выделенный фрагмент
  исходного (до 500 символов): `{"__rst":1,"t":"текст","q":"фрагмент"}`, вместе с
  обычным `reply_to`. Показывать над ответом `q` вместо начала исходного. Правка
  ответа сохраняет `q`. Клиент без поддержки покажет цитату по-старому.
* **«Прослушано».** У сообщения поле `played` (в истории и в `new_msg`; новые —
  `false`, всё отправленное до 2026-10-04 — `true`). Получатель (в группе — любой
  участник, кроме автора) после включения голосового/кружка шлёт
  `{"action":"played","message_id":N}`; сервер рассылает чату
  `{"action":"msg_played","id":N,"receiver":...}`. Веб: точка у длительности,
  пока `played == false`.
* **Подпись участника группы.** `POST /api/groups/member_title
  {group_id, target_username, title}` (до 32 символов, без `<>`; пусто — снять):
  владелец и админы — любому, участник — себе. В `/api/groups/{id}/info`
  `members[].title`; событие всем участникам
  `{"action":"member_title","group_id","username","title"}`. Веб: подпись
  рядом с именем отправителя в ленте и в составе.
* **Викторина.** В настройках опроса `poll.correct` — номер правильного варианта
  (только при `multiple: false`). В состоянии опроса `quiz: true`; `correct`
  приходит ответившему (и в личном `poll_update` полем `correct`), автору и всем
  после завершения. Ответ нельзя изменить или отменить (ошибка).
* **«@онлайн»** (и `@online`) в тексте — упоминание только для того, кто сейчас
  смотрит на экран; решает получатель сам. В подсказке «@» пункт «Все, кто в сети».

### Каналы, темы, автоответ, стикеры (с 2026-10-04)

* **Канал** — группа с `kind: "channel"`. Создание: `POST /api/groups/create`
  с `"kind": "channel"` (участников, кроме себя, можно не звать). Пишут только
  владелец, админы и редакторы (`admins_only` всегда `true`, выключить нельзя —
  400). Служебных строк «вступил/вышел» в канале нет. `kind` приходит в
  `/api/contacts` (`groups[].kind`), в поиске публичных групп и в
  `/api/groups/{id}/info` (там же `subscribers` — число подписчиков). Подписчику
  (не owner/admin) `members` в info содержит только его самого — подписчики друг
  друга не видят. Веб: «Создать канал» в меню нового чата; в ленте канала нет
  аватара и имени автора (пост — от имени канала), нет кнопок звонка, в шапке
  «📣 Канал · N подписч.», в панели — «Подписчики» вместо «Участники».
* **Темы в группах** (как «Темы»/форум в Telegram; `routers/topics.py`). Ветки
  «у сообщения» (`thread_id`) **отменены** — сервер их больше не принимает и не
  отдаёт; не делать.
  - Включает/выключает владелец или админ: `POST /api/groups/{n}/forum
    {"enabled": true}` (в канале — 400). Всем участникам событие
    `{"action":"group_forum","group":"group_N","forum":bool}` и служебная строка.
    `groups[].forum` в `/api/contacts`.
  - Группа с `forum: true` открывается **списком тем** вместо ленты:
    `GET /api/groups/{n}/topics` → `{forum, can_manage, can_create, topics:[{id,
    title, icon, closed, general, created_by, unread, last_msg:{id, sender,
    content, file_type, file_url, time}}]}`. Первой всегда «Общее» (`id: 0`,
    `general: true`, иконка «#»), дальше по свежести. `icon` — эмодзи, пусто —
    цветная буква названия. `content` — шифр ключом группы (превью «Имя: текст»).
  - Тема — отдельная переписка: `send` с `"topic_id": N` (0 или нет — «Общее»);
    `new_msg` и история несут `topic_id` (`null` — «Общее»). История темы —
    `GET /api/messages/{me}/group_N?topic_id=N` (`0` — «Общее»). Сообщение другой
    темы в открытую ленту не ставить: это как сообщение из другого чата (счётчик,
    уведомление). Ошибки `send`: «Этой темы нет.», «Тема закрыта: …».
  - Непрочитанные — по каждой теме (`read` как обычно, сервер сам относит его к
    теме сообщения); `groups[].unread` у группы с темами — сумма по темам. Всё до
    включения тем считается прочитанным.
  - `POST /api/groups/{n}/topics {title, icon}` — создать (кто может писать в
    группе; до 100). `PATCH /api/groups/{n}/topics/{id} {title?, icon?, closed?}`
    — название/иконка: автор темы и админы; `closed`: владелец/админы.
    `DELETE …/topics/{id}` — владелец/админы, стирает переписку темы. После любых
    изменений всем `{"action":"topics_changed","group":…, "deleted"?: id}`.
  - Веб: строка темы — иконка, название (🔒 у закрытой), время, «Имя: текст»,
    счётчик; внизу «＋ Новая тема»; правка — правой кнопкой / долгим нажатием
    (название, 18 иконок + «Аа», закрыть/открыть, удалить с подтверждением).
    В теме шапка — иконка и название темы, ниже название группы.
    **Телефон (как Telegram на Android — так же сделать в приложении):** нажатие
    на группу с темами НЕ открывает чат: список чатов сжимается до колонки
    аватарок слева (~78 dp: сверху кнопка поиска, у открытой группы кольцо,
    непрочитанные — кружком на аватарке), справа выезжает панель тем (анимация
    сдвига справа налево). Шапка панели: «←», аватар группы, название,
    «N участников», «＋» новая тема. Нажатие на тему — тема на весь экран;
    «назад» из темы — снова панель тем; «назад»/«←» в панели — панель уезжает
    вправо, список чатов разворачивается. Нижняя навигация остаётся видна.
    Компьютер (как Telegram Desktop): та же панель, но справа сразу открыта тема
    с последним сообщением; «←» убирает панель, тема остаётся. Переключатель «Темы» — в настройках группы (владелец/админ).
* **Автоответ.** Поля профиля `autoreply_on` (bool) и `autoreply_text` (до 500,
  без `<>`, не начинается с `{` и пробела) — в `POST /api/profile/update` и в
  своей записи `/api/contacts`. Пока включён, на **личное** сообщение сервер сам
  шлёт от вашего имени `autoreply_text` — каждому собеседнику не чаще раза в
  6 часов; на автоответ автоответом не отвечает, с поддержкой и при блокировке
  в любую сторону — тоже нет. Сообщение-автоответ: `file_type:
  "application/x-rst-autoreply"`, `file_url: null`, `content` — **открытый текст**
  (не шифр: сервер ключей не знает; клиент показывает как есть, т.к. текст не
  начинается с `{"iv":`). Клиент сам этот `file_type` слать не может (сервер
  молча отбрасывает), при пересылке — сбрасывать в `null`. Веб: пометка
  «↩ Автоответ» над текстом, «Редактировать» в меню нет; настройка — «Настройки
  чатов» → «Когда вы заняты»: переключатель (сохраняется сразу; включение без
  текста подставляет «Сейчас не могу ответить - напишу, как освобожусь.»), поле
  текста с кнопкой «Сохранить текст» и пояснение, что автоответ не защищён
  сквозным шифрованием.
* **Свои стикеры** (`routers/stickers.py`). Набор: `{id, name, title, mine,
  installed, stickers: [{id, file_url, emoji}]}`. `name` — имя для ссылки
  `^[A-Za-z0-9_]{3,32}$`, хранится строчными, уникально.
  - `GET /api/stickers` — добавленные себе наборы (свежие сверху);
  - `POST /api/stickers/sets {title, name}` — создать (сам добавляется себе;
    до 20 своих; занято — 409);
  - `GET /api/stickers/sets/{name}` — набор по имени;
  - `GET /api/stickers/lookup?file_url=` → `{name}` — набор стикера из сообщения
    (404 — набор удалён);
  - `POST /api/stickers/sets/{id}/stickers {file_url, emoji}` — только автор, до
    120; `file_url` — картинка из `/api/upload` **без шифрования**
    (`/uploads/<32hex>.(png|webp|gif|jpg|jpeg)`), `emoji` до 16 знаков;
  - `DELETE /api/stickers/sets/{id}/stickers/{sid}`, `DELETE /api/stickers/sets/{id}`
    — только автор (набор пропадает у всех);
  - `POST|DELETE /api/stickers/sets/{id}/install` — добавить/убрать себе (до 100).

  Отправка стикера: обычный `send` с `file_url` картинки стикера и `file_type:
  "application/x-rst-sticker"`, без конверта вложения (без `k`/`m`); текст —
  шифрованный `"🐱 Стикер"` (эмодзи стикера + «Стикер»), по нему превью в списке
  чатов и цитата в ответе. Сервер принимает только `file_url` существующего
  стикера (иначе ошибка «Этого стикера больше нет.»). Показ: картинка
  ~160 dp без пузыря, нажатие — окно набора («Добавить»/«Убрать», «Ссылка»).
  Веб: вкладка 🖼️ в панели эмодзи (наборы, сверху «＋ Мастерская стикеров»);
  мастерская — создать набор (имя для ссылки подсказывается транслитом названия),
  добавить картинки (ужимаются до 512 px по длинной стороне в WebP; GIF до 1 МБ
  как есть), эмодзи для новых, убрать стикер, удалить набор (двойное нажатие).
  Ссылка на набор: `https://<домен>/chat?stickers=<name>` — после входа открывается
  окно набора. «Бота» как отдельного собеседника нет: с E2E бот не прочёл бы
  присланные ему картинки и команды, поэтому мастерская встроена в приложение.

### Прочитано на другом своём устройстве (с 2026-10-04)

После каждого `read` сервер шлёт **остальным** соединениям читателя (не тому,
что прислал `read`): `{"action":"chat_read","chat":"<ник собеседника или
group_N>","unread":N}`; в группе с темами ещё `"topic": id (0 — «Общее")`,
`"topic_unread": M`. `unread` — новый счётчик чата, считается как в
`/api/contacts`: в личке — сообщения собеседника со статусом `sent`; в группе —
`id > last_read_msg_id`; в группе с темами — сумма по темам. Клиент ставит
счётчику чата `unread`, обновляет открытый список тем этой группы и при
`unread == 0` снимает уведомления этого чата. Событие приходит, даже если у
читателя скрыто «Прочитал(а)».

Отмечать прочитанным — только когда чат действительно перед глазами: веб —
вкладка видна **и** окно в фокусе (иначе отметки ждут возврата в окно); Android —
экран чата RESUMED (не процесс). В группе `read` идёт с `sender = "group_N"`.

### Комментарии к постам канала (с 2026-10-05)

* Комментарий — `send` в канал с `"comment_to": <id поста>`. Пост — обычное
  сообщение этого канала, не служебное и не комментарий; иначе ошибка «Этого
  поста нет.»; в обычной группе — «Комментарии есть только в каналах.».
  Комментировать может **любой подписчик** (обычное `admins_only` канала на
  комментарии не действует). Нельзя отложить и нельзя опрос.
* `new_msg` комментария несёт `comment_to` и `silent: true` (push нет никому).
  В ленту канала не ставить, в превью списка чатов и непрочитанные не считать —
  сервер их тоже не считает (`/api/contacts`, `chat_read`).
* История канала без параметра — только посты (`thread_id IS NULL` на сервере),
  у каждого поста `comment_count`. Комментарии поста —
  `GET /api/messages/{me}/group_N?comment_to=<id>`.
* Шифрование — ключом канала, как посты. Удаление — обычным `delete_msg`
  (`both`): свой комментарий — автор, любой — владелец/админ.
* Веб: под каждым постом полоса «💬 N комментариев» / «Прокомментировать»;
  нажатие — панель (на телефоне на весь экран): пост сверху, комментарии
  (аватар, имя, текст, время; свои справа), поле «Комментировать…». Удалить —
  правой кнопкой/долгим нажатием.

### Черновики на всех своих устройствах (с 2026-10-05)

* `PUT /api/drafts {"chat": "<ник или group_N>", "content": "<шифр>"}` —
  сохранить черновик чата; пустой `content` — стереть (после отправки
  сообщения или если текст убрали). Ответ `{updated_at}`. `GET /api/drafts` →
  `{drafts: [{chat, content, updated_at}]}`.
* `content` шифруется **ключом «Избранного»** (общий ключ с самим собой, тот же,
  что для переписки с собой) — его знают только свои устройства; внутри —
  текст с разметкой как в поле ввода. Сервер текста не видит.
* После каждого `PUT` всем своим соединениям: `{"action":"draft","chat",
  "content","updated_at"}`. Применять, если не старше своего и этот чат сейчас
  не правят (поле ввода в фокусе) — тогда не трогать.
* Веб: сохранение с задержкой 1,5 с после правки; при входе — черновики с
  сервера, более свежие побеждают; в списке чатов «Черновик: …».

### Местоположение в реальном времени (с 2026-10-05)

* Сообщение с `file_type: "application/x-rst-live-location"`; зашифрованный
  конверт: `{"__rst":1,"t":"📍 Геопозиция в реальном времени","g":{"lat","lon",
  "acc","until","ts","stopped"}}` — `until`, `ts` в миллисекундах эпохи,
  `stopped: true` у последней точки. `t` — для прежних клиентов и превью.
* Новая точка — кадр `{"action":"live_location","message_id":N,"content":"<новый
  конверт>"}`: только автор и только такое сообщение; не чаще раза в 3 с (чаще —
  молча отбрасывается). Сервер подменяет содержимое **без** «изменено» и
  рассылает чату (и эхом автору) `{"action":"live_location","id","sender",
  "receiver","content"}`. История отдаёт последнюю точку.
* Веб: «Местоположение» в скрепке → выбор «Отправить текущее место» / делиться
  15 минут / 1 час / 8 часов. Карточка: пульсирующая метка, «осталось N мин ·
  обновлено …», «Открыть на карте» (OSM), у автора — «Остановить». Точка
  обновляется раз в 10 с или при сдвиге больше 30 м; срок вышел или
  «Остановить» — последняя точка с `stopped`. После перезагрузки трансляция
  продолжается. Править такое сообщение нельзя; при пересылке тип сбрасывается.
  На Android трансляция может идти в фоне (foreground-сервис) — это лучше веба.

### Обрезка видео и кружков (с 2026-10-05, только клиент)

* Протокол не меняется: обрезанное уходит обычным вложением/кружком.
* Веб: в окне отправки видео — «Обрезать»: превью по кругу, полоса времени с
  двумя ручками (начало/конец, не короче 1 с), «0:03 … 9 с … 0:12». Во время
  записи кружка без рук рядом с таймером «✂» — остановить и обрезать, затем
  «Отправить». Веб режет перекодированием в реальном времени (холст + WebAudio →
  MediaRecorder), на Android лучше Media3 Transformer / MediaMuxer без потерь.

### Любая реакция: эмодзи и стикеры (с 2026-10-05)

* `reaction` принимает **любой эмодзи** (один значок, в т. ч. составной: ZWJ,
  флаги, цвет кожи, VS16; до 16 знаков, без ASCII, пробелов и разметки) или
  **стикер** — строку `"s:/uploads/<32hex>.(png|webp|gif|jpg)"` существующего
  стикера. Остальное сервер молча отбрасывает.
* В `reactions` значение может быть `s:/uploads/…` — рисовать картинкой
  стикера (~20 dp в значке, ~24 dp в списке «кто поставил»), не текстом.
* Веб: в меню сообщения после «+» — «Любая…»: окно с вкладками «Эмодзи» (все
  категории панели эмодзи) и «Стикеры» (свои наборы).

### Несколько аккаунтов на устройстве (с 2026-10-05, только клиент)

* Протокол не меняется. Веб: «Настройки» → блок аккаунтов под профилем
  (текущий с галочкой, у остальных — непрочитанные, запрошенные их токеном),
  «Добавить аккаунт» → вход (там же «вернуться в аккаунт…»). До 5 аккаунтов.
* Хранение: у каждого — свой токен и свой ключ расшифровки (на вебе — отдельный
  неизвлекаемый CryptoKey в IndexedDB), переключение — перезапуск интерфейса в
  выбранном аккаунте. Сокет — только у активного; push приходят на все
  (на Android — FCM-токен регистрируется для каждого аккаунта).
* Выход из одного аккаунта убирает только его (кэш, ключ, push на сервере для
  этого аккаунта, подписка устройства остаётся остальным) и переключает на
  следующий.
* Push нескольким аккаунтам (с 2026-10-05): уникальна пара (FCM-токен,
  аккаунт) и (endpoint веб-подписки, аккаунт) — `POST /api/push/fcm/register`
  тем же токеном из второго аккаунта больше **не отбирает** push у первого;
  `fcm/unregister` снимает токен только для своего аккаунта. В data каждого
  FCM-push (`t: msg`, `t: call`) и в каждом web-push — поле `"to": "<ник
  получателя>"`; push по группе уходят каждому аккаунту отдельно.

### Альбомы (с 2026-10-07, только клиент)

* Несколько вложений, выбранных разом, уходят **альбомом**, как в Telegram.
  Каждое вложение — по-прежнему отдельное сообщение (`send` с `file_url`),
  общее у них — поле `"a"` в зашифрованном конверте вложения: случайная
  строка `[A-Za-z0-9_-]{1,64}` (веб берёт 16 hex-знаков). Сервер о
  группировке не знает, протокол не меняется. Другие значения `a` — игнорировать.
* Отправка: фото и видео — альбомами по 10, остальные файлы — отдельными
  альбомами по 10 (смешанный выбор делится на два). Сначала шифруются и
  загружаются все файлы пачки, затем сообщения отправляются подряд — у
  получателя альбом появляется целиком. Ответ (`reply_to`) — только у
  первого. Выбран один файл — обычное сообщение без `a`.
* Подпись (с 2026-10-07): текст из поля ввода — полем `t` **первого фото или
  видео** альбома (у остальных `t` пустой). Показывается под сеткой, с
  оформлением, как подпись одиночного фото. Если выбраны одни документы —
  подпись уходит отдельным текстовым сообщением следом (у документа `t`
  показывается как имя файла). После отправки поле ввода и черновик чистятся.
  Правка подписи сохраняет `a` в конверте, иначе вложение выпадет из альбома.
* Подпись у видео (не кружка) теперь показывается под ним, как у фото; `t`,
  похожий на имя файла (`имя.mp4` без пробелов), подписью не считается.
* Показ: подряд идущие сообщения одного автора с одинаковым `a` (не больше 10)
  — один пузырь. Фото/видео — сеткой из рядов по 2–3: 2 → [2], 3 → [1,2],
  4 → [2,2], 5 → [2,3], 6 → [3,3], 7 → [2,2,3], 8 → [2,3,3], 9 → [3,3,3],
  10 → [2,2,3,3]; файлы — списком в одном пузыре. Время и галочки — одни на
  альбом.
* Каждое вложение остаётся своим сообщением: меню (удержание/правая кнопка)
  на ячейке — для этого вложения (удалить, переслать, ответить, реакция).
  Выделение (с 2026-10-07): удержание фото или «Выбрать» в его меню — только
  это вложение (галочка на ячейке, фото чуть уменьшается); нажатие на пузырь
  альбома вне фото (подпись, время, кружок выбора строки) — весь альбом.
  Кружок строки отмечен, только когда выбраны все вложения.
* Просмотр фото (с 2026-10-07): листание по всем фото переписки в порядке
  ленты (внутри альбома — по порядку сетки): смахивание влево-вправо, стрелки,
  счётчик «2 / 5». Удалили любое вложение, в том числе первое, —
  альбом пересобирается из оставшихся; осталось одно — обычное сообщение.

### Хэштеги, контакт, «❤», картинка в картинке, одноразовые (с 2026-10-08)

* **Хэштеги** (только клиент): `#тег` (буквы любого алфавита, цифры, `_`, до 64)
  после пробела или в начале строки — кнопка; нажатие — поиск по чату с этим
  тегом. Внутри слова (`a#b`) и в ссылке (`/#frag`) — не тег.
* **Поделиться контактом** (только клиент): меню скрепки → «Контакт» → выбор из
  своих чатов. Сообщение — обычный текст `«👤 Контакт: Имя (@ник)»` (его увидят
  старые клиенты), а в зашифрованном конверте поле **`c`: `{"u": "ник", "n":
  "Имя"}`** (`u` — `[A-Za-z0-9_-]{1,64}`, `n` — до 64 знаков; иначе игнорировать).
  Конверт создаётся и без файла: `{"__rst":1,"t":"…","c":{…}}`. В ленте —
  карточка: аватар, имя, @ник, «Написать» (открыть чат). В превью списка —
  значок человека и «Имя (@ник)».
* **Новые реакции на мои сообщения — «❤»** (сервер, `routers/reactions_unread.py`):
  кто-то поставил реакцию на моё сообщение — у меня запись «новая», снял —
  запись уходит. `GET /api/reactions/unread?chat=<ник|group_N>` →
  `{items:[{message_id, reactor, emoji}]}` по порядку; `POST /api/reactions/seen
  {chat, ids:[…]}` — увидел. В `/api/contacts` у каждого чата
  **`unread_reactions`** (сообщений с новыми реакциями) — красный значок «❤» в
  строке. В открытом чате — круглая «❤» со счётчиком (над «@», если та видна);
  нажатие — к самому раннему сообщению, давнее догружается; сообщение
  наполовину на экране — `/seen`. На `reaction_update` по моему сообщению —
  перечитать список.
* **Видео звонка поверх окон** (только клиент): свернули видеозвонок — видео
  собеседника в системное окно «картинка в картинке» (на Android — PiP
  Activity); развернули — назад. Голосовой — без окна.
* **Одноразовые фото и видео** (сервер, `routers/viewonce.py`): в окне отправки
  одного фото/видео в **личке** — «Одноразовое». Кадр `send` с
  **`"view_once": true`** (сервер примет только с `file_url`, только в личке,
  не себе). У сообщения поле **`view_once`** (в `new_msg` и в истории). Получатель
  видит не картинку, а кнопку «Одноразовое фото · нажмите, чтобы открыть»; по
  нажатию — скачать и расшифровать **в память, без кэша**, показать отдельным
  окном без «Сохранить» (на Android — FLAG_SECURE от снимков экрана), затем
  **`POST /api/messages/{id}/consume`** — сервер стирает файл и `file_url`, обоим
  `{"action":"view_once_opened","id","receiver"}`. Без `file_url` — «Одноразовое
  фото · Просмотрено». Отправитель видит «Откроется один раз» и открыть не может.
  Переслать, копировать, править одноразовое нельзя. Подписи нет.

### Свернуть звонок и сетка группового звонка (с 2026-10-08, только клиент)

* У экрана звонка (вдвоём и группового) — кнопка «Свернуть» (слева вверху), на
  телефоне «назад» во время звонка тоже сворачивает. Свёрнутый звонок —
  зелёная плашка сверху по центру колонки чата: «Имя · 1:23 · Вернуться» и
  красная трубка «Завершить»; нажатие на плашку — развернуть. Разговор, звук и
  видео не прерываются, можно ходить по чатам и писать. Звонок закончился —
  плашка исчезает. Сервер не участвует.
* Сетка группового звонка: число колонок и размер плиток (4:3) подбираются под
  свободное место — все участники на экране без прокрутки и не под кнопками
  (раньше одна плитка на широком экране была выше экрана и прокручивалась).
  Прокрутка — только если даже при ширине 160 px не помещаются.

### Вход по QR-коду (с 2026-10-08)

Сервер — `routers/qrlogin.py` (сеансы в памяти, живут 180 с), веб — `js/qr-login.js`.
Новое устройство показывает код, вошедшее его сканирует и подтверждает.

**Новое устройство** (веб: «Войти по QR-коду» на странице входа):
1. Одноразовая пара ECDH P-256. `pub` = открытый ключ в **сыром** виде
   (65 байт, 0x04‖X‖Y), base64url без `=` (87 знаков).
2. `POST /api/qr/start {pub}` → `{session, secret, expires_in}`. `secret` никуда не
   показывать: им забирают результат.
3. QR-код: `https://<домен>/chat#qr=<session>.<pub>` (всё после `#` на сервер не уходит).
4. Раз в 2 с `POST /api/qr/poll {session, secret}` → `{status:"pending"}` /
   `{status:"denied"}` / **410** (код устарел — показать новый) / при подтверждении
   `{status:"approved", username, original_username, kdf_salt, kdf_iterations,
   access_token, payload, approver_pub}` — выдаётся **один раз**.
5. Общий ключ = ECDH(своя одноразовая приватная, `approver_pub`) — 32 байта общего
   секрета (координата X) **напрямую** ключом AES-GCM-256, без KDF (так делает
   WebCrypto `deriveKey`). `payload` — JSON `{iv, ct}`, оба в обычном base64;
   `ct` = шифротекст‖тег. Открытый текст — JSON `{"v":1,"priv":"<JWK-строка
   приватного ключа аккаунта>"}` (тот же JWK, что лежит в `encrypted_private_key`).
6. Пароля у устройства нет: веб создаёт случайный ключ устройства вместо ключа
   из пароля и хранит приватный ключ у себя (`localStorage.device_private_key`,
   AES-GCM под ключом устройства), копия на сервере не используется. Смена пароля
   или вход по паролю на этом устройстве эту копию убирают.

**Подтверждающее устройство** (уже вошло): открыли адрес из кода (камера / ссылка
`https://<домен>/chat#qr=…`; на Android — сканер и/или приём такой ссылки):
1. `GET /api/qr/{session}` (с токеном) → `{device, ip, age}`; 409 — код уже
   использован, 410 — устарел.
2. Окно «Войти на другом устройстве?»: устройство, адрес и предупреждение
   («подтверждайте, только если сами входите и видите код на его экране; если код
   прислали — мошенники»). «Отмена» → `POST /api/qr/deny {session}`.
3. «Подтвердить»: своя одноразовая пара ECDH P-256; общий ключ = ECDH(своя
   одноразовая приватная, `pub` **из QR-кода**, не с сервера); зашифровать
   `{"v":1,"priv":"<JWK-строка>"}` (AES-GCM, iv 12 байт) и `POST /api/qr/approve
   {session, pub, approver_pub, payload}` — `pub` из кода (сервер сверяет с
   сеансом, иначе 400), `approver_pub` — своя одноразовая открытая (сырая,
   base64url), `payload` — JSON `{iv, ct}` строкой.

### Ссылки-приглашения и заявки на вступление (с 2026-10-08)

Сервер — `routers/invites.py`. Управляют владелец и админы группы (иначе 403).

* `GET /api/groups/join/{token}` — `token` теперь основная ссылка (`invite_hash`)
  **или** дополнительная. Ответ `status`: `ok` / `already_member` / **`requested`**
  (заявка отправлена, участником ещё не стал; `group_id`, `name`). Ошибки: 404
  (нет/отозвана), **410** (срок истёк / предел исчерпан), 403 (бан).
  `POST /api/groups/join_public` тоже может вернуть `requested`.
* Заявитель: при `requested` ключ из `#k=` сохранить у себя до одобрения
  (веб: `localStorage.rst_pending_group_keys[group_id]`) и при одобрении
  сразу `set_my_key` — до одобрения сервер ключ не примет (не участник).
* `ChatGroup.join_approval`: `POST /api/groups/settings {group_id, join_approval}`;
  в `GET /api/groups/{id}/info` — `join_approval` и `join_requests` (число
  ждущих; не-админам 0). Включено — по основной ссылке и через «Вступить» в
  публичной группе вступают через заявку.
* Дополнительные ссылки:
  `GET /api/groups/{id}/invites` → `{invites:[{id, token, title, created_by,
  created_at, expires_at, usage_limit, usage_count, approval, state}],
  join_approval, requests}`; `state` — `active|expired|exhausted` (отозванные
  не отдаются). `POST /api/groups/{id}/invites {title?, expires_in, usage_limit?,
  approval}` — `expires_in` ∈ {0 (без срока), 3600, 86400, 604800, 2592000},
  `usage_limit` 1…100000 или null; не больше 50 ссылок. `POST
  /api/groups/{id}/invites/{invite_id}/revoke`. Адрес ссылки — как у основной:
  `https://<домен>/join/<token>#k=<ключ группы>`.
* Заявки: `GET /api/groups/{id}/requests` → `{requests:[{username, name,
  avatar_url, created_at, via}]}` (`via` — название ссылки или пусто);
  `POST /api/groups/{id}/requests/{username}/approve|decline` → `{approved}`.
  Одобренный становится участником (служебная строка «X вступил в группу
  (заявку одобрил Y)», ему `group_added`).
* WebSocket: админам — `{"action":"join_request","group_id","username"}` (новая
  заявка; веб показывает уведомление) и `{"action":"join_request_resolved",
  "group_id","username"}`; заявителю — `{"action":"join_request_done",
  "group_id","name","approved":bool}`.
* Веб: в настройках группы под основной ссылкой — переключатель «Заявки на
  вступление» и кнопка «Ссылки и заявки» (со счётчиком): окно со списком
  заявок (Принять / ✕) и дополнительных ссылок (Копировать / Отозвать) и
  формой новой (название, срок, предел, «через заявку»).

### Кнопка «@» — к непрочитанным упоминаниям (с 2026-10-08, только клиент)

* Над кнопкой «вниз» в открытом чате — круглая «@» со счётчиком (число — от
  двух). Видна, пока есть упоминания меня (как подсветка `mentions-me`:
  `@ник`, `@все`, `@онлайн` в момент прихода), которые ещё не попадались на
  глаза: среди непрочитанных на момент открытия чата (последние `unread`
  чужих сообщений первой порции) и пришедших при открытом чате.
* «Увидено» — пузырь хотя бы наполовину побыл на экране при видимом
  приложении. Нажатие — прокрутка к самому раннему из оставшихся (с
  подсветкой). Удалённое сообщение с кнопки убирается. Сервер не участвует.

### Исправления 2026-10-12: удалённое «у себя», «❤», одноразовые, отложенные, превью ссылок

* **Превью ссылки — без фрагмента.** Перед `GET /api/link-preview?url=…` отрезать
  всё после `#`: в ссылках-приглашениях там ключ группы (`#k=…`), и он уходил на
  сервер (сервер теперь тоже отрезает, но ключ не должен покидать устройство).
* **`/api/contacts` → `last_msg`** больше не бывает сообщением, удалённым «у себя»
  (ни в личке, ни в группе); после «Очистить историю у себя» — `null`.
* **Список чатов после удаления.** На `msg_deleted` (если это было последнее
  сообщение чата или сообщение не в открытом чате) и на `chat_cleared` —
  перезагрузить `/api/contacts` (веб — один раз через 0,4 с после серии
  событий): иначе превью и счётчик непрочитанных висят до перезагрузки.
* **«❤» в списке — сразу.** Новое событие автору сообщения:
  `{"action":"reactions_unread_changed","chat":"<ник|group_N>","message_id"}` —
  кто-то поставил или снял реакцию на моё сообщение. `chat` — как чат видит
  автор. Если этот чат не открыт — перечитать `/api/contacts` (там
  `unread_reactions`). На своих сообщениях, удалённых «у себя», новых реакций нет
  (удаление у себя и очистка чата их снимают).
* На `msg_deleted` убрать сообщение и из списка кнопки «❤» (как из «@»).
* **Одноразовое не пересылается и из выделения.** Сервер отклоняет кадр `send`,
  чей `file_url` принадлежит одноразовому сообщению: `{"action":"error",
  "message":"Одноразовое фото или видео переслать нельзя."}`. Пересылку
  выбранных сообщений — без одноразовых (веб: подсказка «Одноразовые фото и
  видео не пересылаются»).
* **Отложенное — в свою тему.** `topic_id` в кадре `schedule` теперь сохраняется
  (раньше отложенное из темы уходило в «Общее»); при отправке тема проверяется
  заново (удалена/закрыта — `scheduled_failed`). `GET /api/scheduled` отдаёт
  `topic_id`. Вложение отложенного сообщения уборка файлов больше не трогает.

### Подтверждение вступления по ссылке (с 2026-10-12)

Ссылка-приглашение (`/join/<token>#k=…`, короткая `/<псевдоним>`) больше не
вступает сразу. Сначала **`GET /api/groups/join/{token}/preview`** (ничего не
меняет; ошибки те же, что у вступления: 404 нет/отозвана, 410 срок/предел, 403
исключён) → `{group_id, name, description, avatar_url, kind, members, approval,
is_member, requested}`.
* `is_member` — сразу открыть чат, без окна.
* `requested` — заявка уже ждёт: сообщить «заявка уже отправлена», ключ из `#k=`
  сохранить как ждущий (как при `requested` от вступления).
* Иначе окно: аватар, название, «Группа · N участников» / «Канал · N
  подписчиков», описание (до 500 знаков), при `approval` — пометка «Вступление по
  заявке: её рассмотрят администраторы группы». Кнопки «Отмена» и «Вступить» /
  «Подписаться» (канал) / «Подать заявку» (`approval`). Только по нажатию —
  `GET /api/groups/join/{token}` и дальше как раньше (ключ, открыть чат).
  «Назад», Esc и нажатие мимо окна — отмена, вступления нет.

### Плотные пузыри текстовых сообщений (с 2026-10-12, только клиент)

Как в Telegram: у текстового сообщения время (с галочками и «изменено») стоит
**в конце последней строки текста**, если там хватает места, и переносится на
новую строку только когда не помещается. Раньше под текстом всегда была
отдельная строка под время, и даже «Огонь» был пузырём в две строки.
* Приём: невидимая копия подписи (та же ширина: «(изменено)», галочки, время)
  идёт сразу за текстом в том же потоке строк, а видимая подпись прижата к
  правому нижнему углу пузыря. На Android — свой лэйаут пузыря: измерить
  ширину последней строки текста (`Layout.getLineWidth(lastLine)`); если
  `ширина строки + отступ 10dp + ширина подписи` ≤ максимальной ширины
  пузыря — подпись на той же строке справа, иначе — отдельной строкой снизу.
* Отступы текстового пузыря: 6dp сверху и снизу, 10–11dp по бокам; подпись —
  6dp от низа и 10dp от правого края.
* Так — только обычный текст (в том числе с ответом, пересылкой, именем
  автора в группе). У вложений, опросов, контакта, геопозиции, больших эмодзи
  и постов канала с комментариями — как было. Превью ссылки — под текстом, время
  под ним.
* Сервер не участвует.

### Недавние действия — журнал администраторов группы (с 2026-10-17)

Сервер — `routers/admin_log.py`. Пишется сам при действиях администраторов;
клиенту — только показать.
* `GET /api/groups/{group_id}/admin_log?before=<id>&limit=<до 50>` — только владельцу и
  администраторам (иначе 403). Ответ `{items:[{id, action, created_at,
  actor, actor_name, target, target_name, details}], has_more}`, новые сверху;
  следующая страница — `before` = id последней. Хранится 90 дней.
* `action` и `details`:
  - `member_added`, `member_kicked`, `member_banned`, `member_unbanned` — `target` участник;
  - `role_changed {role}` (admin/editor/helper/member), `owner_transferred`, `title_changed {title}` (пусто — подпись убрана);
  - `info_changed {fields:[name|description|avatar_url], name?}`;
  - `public_changed {on}`, `admins_only_changed {on}`, `join_approval_changed {on}`, `forum_changed {on}`;
  - `slow_mode_changed {seconds}` (0 — выключен), `timer_changed {seconds}` (0 — выключено);
  - `alias_changed {alias}` (пусто — убрана), `invite_reset`, `invite_created {title}`, `invite_revoked {title}`;
  - `request_approved`, `request_declined` — `target` заявитель;
  - `message_deleted {message_id}` (чужое сообщение удалил админ), `message_pinned {message_id}`,
    `message_unpinned {message_id}` — `target` автор сообщения;
  - `topic_closed {title, closed}`, `topic_deleted {title}`.
  Неизвестное `action` показывать как «Имя: action» — не прятать.
* Веб (`js/admin-log.js`): в карточке группы у владельца и админов — строка
  «Недавние действия» (значок часов) → окно со списком: значок (красный —
  исключение/бан/удаление/отзыв/отклонение, булавка — закреп), фраза «**Иван**
  исключил(а) **Пётр**», время «17 окт., 16:24»; «Показать ещё»; запись о закрепе
  нажимается — переход к сообщению. Тексты фраз — `describeAction` там же.

### Фото и видео под спойлером (с 2026-10-17, только клиент)

* В зашифрованном конверте вложения новое поле **`h`: `1`** — «скрыто под
  спойлер»: `{"__rst":1,"t":"…","k":"…","n":"…","m":"image/png","h":1}`. Только
  для фото и видео (кружки и одноразовые — без него). Любое другое значение —
  не спойлер. Сервер не участвует.
* Отправка: в окне отправки одного фото/видео — «Скрыть под спойлер — размыто,
  пока не нажмут» (в любом чате). При правке подписи `h` сохранять (конверт
  собирается заново).
* Показ: размытие (веб — blur 24px), мерцающая «пыль» и пометка «Спойлер»
  посередине. **Первое нажатие только раскрывает** (не открывает просмотр и не
  запускает видео), дальше — как обычно. Раскрытие не запоминается: после
  перезагрузки снова скрыто. В альбоме — у каждой ячейки отдельно; скрытые не
  листаются в просмотре. Превью в списке чатов — как у обычного фото.

### «@все» и упоминания доходят в заглушённой группе (с 2026-10-18)

* **Отображение.** `@все`, `@онлайн`, `@all`, `@online` (после пробела или в
  начале, без продолжения буквой/цифрой/`_`/`-`) — подсветка как упоминание,
  **без перехода в профиль** (раньше `@all` вёл в профиль пользователя «all»,
  а кириллическое `@все` не подсвечивалось).
* **Подсказка серверу при отправке в группу** (кадр `send`, не пересылка):
  `"mention_all": true`, если в тексте есть `@все`/`@all`; `"mentions": [ники]` —
  `@ник` латиницей `[A-Za-z0-9_-]{1,32}`, без all/online, по разу, до 50. Текст
  не передаётся. Сервер оставляет только участников группы и не отправителя;
  `mention_all` принимает только от владельца и админов (иначе false).
  В `new_msg` приходят `mention_all` и `mentions` (уже очищенные).
* **Push.** Упомянутым (или всем при `mention_all`) — и в заглушённой группе;
  тихие часы и выключенные уведомления групп целиком действуют. Текст web-push:
  «Имя упомянул(а) вас» / «Имя: @все». **FCM: в данных `"m": 1`** — показать
  уведомление, даже если чат заглушён (у получателя упоминание).

### История правок сообщения (с 2026-10-18, только клиент)

* При правке в конверт добавляется поле **`e`: `[{"t": "прежний текст", "at": мс}]`**
  — прежние версии, старые первыми, **не больше 10** (последние). При каждой
  правке к списку из текущего конверта дописывается текст *до* этой правки.
  Конверт создаётся и у простого текста, если есть `e`:
  `{"__rst":1,"t":"новый текст","e":[{"t":"старый","at":1792304646618}]}`.
  Принимать только элементы с `t`-строкой (до 4096), `at` — число, иначе 0.
  Сервер не участвует (весь конверт шифруется).
* Показ: у изменённого сообщения «(изменено)» с пунктирным подчёркиванием
  нажимается (если `e` есть) → окно «История правок»: «Сейчас» (текущий текст,
  подсвечено) и прежние версии с датой «18 окт., 14:24», новые сверху.
* Правку **своих** конвертов собирать с сохранением `e` (и `x`, см. ниже).

### «Напомнить» о сообщении (с 2026-10-18)

* Пункт меню сообщения «Напомнить» (иконка колокольчик; у одноразовых нет) →
  окно выбора времени (как у отложенных: «Через час», «Сегодня в 18:00»,
  «Завтра в 9:00», своё время).
* Это **отложенное сообщение себе** (`receiver` = свой ник): кадр `schedule`
  с **`"reminder": true`** и `send_at`. Содержимое — копия текста (и вложения:
  тот же `file_url`, ключ в конверте, `file_type` `application/octet-stream`),
  в конверте поле **`r`: `{"c": "чат", "i": номер_сообщения, "n": "имя чата"}`**
  (`c` — ник или `group_N`, `[A-Za-z0-9_-]{1,80}`; `n` до 64). `reminder` вне
  Избранного сервер игнорирует (обычное отложенное).
* `scheduled_saved` и `GET /api/scheduled` — новые поля `reminder`,
  `when_online`. Тост: «Напомню завтра в 09:00». Полоса над лентой Избранного:
  «Напоминание: …» / «Напоминаний: N», в списке — 🔔 перед временем.
* Когда время пришло: в Избранное приходит `new_msg` с **`"reminder": true`**
  (отправитель — сам человек). Открытый клиент показывает уведомление
  «🔔 Напоминание» с текстом, если Избранное не открыто перед глазами.
  Закрытый — push: web-push «🔔 Напоминание / Сообщение в Избранном»;
  **FCM: `{"t":"msg","chat":"<свой ник>","id":…,"r":1}`** — показать
  уведомление, хотя сообщение своё. Напоминание будит **всегда**: и в
  заглушённом Избранном, и в тихие часы, и при выключенных уведомлениях.
* В пузыре над текстом — плашка «🔔 **Напоминание** · Имя чата» (как строка
  «Переслано»); нажатие открывает чат `c` и прокручивает к сообщению `i`
  (если чата нет в списке — «Этого чата больше нет в списке»).

### Ответ на сообщение в другом чате (с 2026-10-18, только клиент)

* Пункт меню сообщения «Ответить в другом чате» → окно выбора чата (поиск,
  Избранное первым, без текущего и системных) → открывается выбранный чат,
  над полем ввода индикатор ответа: «Автор · Имя исходного чата» и текст.
  Esc / ✖ отменяет.
* Первое отправленное сообщение в этот чат (текст, файл, стикер; у альбома —
  первое вложение) несёт в конверте поле **`x`: `{"a": "автор", "t": "текст",
  "n": "имя чата"}`**: `a` до 64 — **отображаемое имя автора** (своё — своим
  именем, не «Вы»), `t` — до 300 символов + «…» (вложение без подписи —
  «📎 Вложение»), `n` до 64 — имя исходного чата; для Избранного **пусто**.
  Номера исходного чата и сообщения нет — собеседник его не прочтёт.
  `reply_to` при этом не ставится.
* Показ: блок как у обычного ответа (полоса слева): «Автор · Имя чата»
  (пустое `n` → «из другого чата»), ниже текст в одну строку с оформлением.
  Не нажимается. При правке такого сообщения `x` сохранять.

### «Отправить, когда будет в сети» (с 2026-10-18)

* В меню над «Отправить» (удержание / правая кнопка) — «Когда будет в сети»;
  только в личном чате (не группа, не Избранное, не системный).
* Кадр `schedule` **без `send_at`**, с **`"when_online": true`**. Ответ:
  `scheduled_saved` с `when_online: true` (`send_at` — запасной срок через
  год); тост «Сообщение уйдёт, когда Имя будет в сети». Если собеседник уже
  в сети — сервер отправляет сразу (`scheduled_saved` не приходит, приходит
  `new_msg`). В группе и себе — `error`.
* Отправляется, как только собеседник появится «в сети» (то же событие, что
  `presence online`; невидимку не выдаёт — у неё не срабатывает), приходит
  `scheduled_sent`. В списке отложенных вместо времени — «когда собеседник
  будет в сети»; «Отправить сейчас» и «Удалить» работают как обычно.

### Поиск во всей истории (с 2026-10-18, только клиент)

* Сервер хранит шифротекст и искать не может; общий поиск находит только
  расшифрованное на устройстве. Под результатами поиска (запрос от 2 символов)
  — кнопка «Искать во всей истории» с пояснением «Переписка всех чатов
  загрузится и расшифруется на этом устройстве». По нажатию: для каждого чата
  (Избранное, личные, группы; без системных) история страницами по 500
  (`GET /api/messages/{me}/{chat}?limit=500&before_id=…`), до 5000 сообщений на
  чат за запуск, расшифровка и сохранение в локальный кэш поиска; прогресс
  «Имя - чат 3 из 12»; затем поиск повторяется.
* Повторно — «Догрузить новое и искать снова» («История загружена 18 окт.,
  14:47»): сверху только новое до уже загруженного, и вглубь, если в прошлый
  раз упёрлись в предел. Заголовок найденного — «во всей загруженной истории».
  Найденное в Избранном подписано «Избранное».

### Эмодзи-статус у имени (с 2026-10-18)

* `PUT /api/emoji_status` `{"emoji": "🏖", "until": "2026-10-25T09:00:00Z" | null}` →
  `{"emoji_status": "🏖", "emoji_status_until": "…Z" | null}`. `emoji` — только
  эмодзи (флаги, ZWJ-семьи, оттенки, `❤️` — да; буквы, цифры, пробелы — 400), до 16
  кодовых единиц; `""` — снять. `until` — в будущем, не дальше года, с поясом;
  `null` — бессрочно.
* Всем на связи — WS `{"action": "emoji_status", "username", "emoji_status",
  "emoji_status_until"}`.
* Поля `emoji_status`, `emoji_status_until` — в `/api/contacts` (у каждого и у себя),
  в поиске `/api/users/search` и в составе группы (`/api/groups/{id}/info` →
  `members[]`). Истёкший статус сервер не отдаёт (`""`), клиент прячет и сам по
  `until`.
* Показ: эмодзи сразу после имени (и после галочки подтверждения) — список
  чатов, шапка, профиль, участники группы, имя автора в группе. В шапке/строке
  «Избранного» свой статус не показывать. Подсказка — «до 19 окт., 21:09».
* Выбор (веб — строка «Эмодзи-статус» под профилем в настройках): сетка частых
  эмодзи + поле «вставьте любой», срок: 1 час / 8 часов / Сутки / Неделя / Без
  срока; «Убрать», если задан.

### Запрет пересылки и сохранения в группе и канале (с 2026-10-18)

* `POST /api/groups/settings` — новое поле `"protected": true|false` (владелец и
  админы); ответ и `/api/groups/{id}/info`, `/api/contacts` (группы) — `protected`.
  При смене — служебная строка «Пересылка и сохранение сообщений из группы
  запрещены / снова разрешены», `group_settings` всем участникам, в журнале
  действий `protected_changed {on}` («запретил(а) / разрешил(а) пересылку и
  сохранение»).
* Сервер: файл (`file_url`) сообщения такой группы нельзя отправить в другой чат,
  в Избранное и в напоминание — `error` «В этой группе запрещено пересылать и
  сохранять сообщения.»
* Клиент в такой группе прячет: «Переслать» (и в выделении), «Копировать»,
  «Ответить в другом чате», «Напомнить», «Ответить лично», «Выделить текст»;
  нет сохранения фото/видео (в просмотре и долгим нажатием), экспорта
  переписки. **Android: `FLAG_SECURE` на экране такого чата** (и просмотра
  его фото/видео). Документы открывать можно. В настройках группы переключатель
  «Запретить пересылку и сохранение — Без пересылки, копирования и сохранения
  фото и видео».

### Чек-листы и опросы со сроком, скрытыми итогами, своими вариантами (с 2026-10-18)

* **Чек-лист** — сообщение-опрос (`file_type` `application/x-rst-poll`) с
  `"poll": {"kind": "checklist", "options": N, "open_add": bool}`, N = 1…30. В
  конверте `p: {"q": "Название", "o": ["Пункт", …], "k": "c"}`, `t`: «☑️ Название».
  Сервер ставит `multiple: true`, `anonymous: false`.
  Отметить/снять пункт — WS `{"action": "check_toggle", "message_id", "option": i}`
  (любой участник; отмечен — снимается, кем бы ни был отмечен). Кто отметил —
  `voters_by_option[i]`. `poll_vote` к чек-листу не применяется.
  Показ: квадратные галочки, отмеченный пункт зачёркнут, справа имя отметившего,
  внизу «Выполнено 2 из 5», «+ Пункт».
* **Опрос**, новые поля в `poll`: `"close_at": ISO с поясом` (≥ +1 мин, ≤ год;
  сервер закроет сам и разошлёт `poll_update` с итогами), `"hide_results": true`
  (итоги — только после завершения, для всех), `"open_add": true` (участники
  добавляют свои варианты; с викториной нельзя).
* **Свой вариант / пункт**: WS `{"action": "poll_add_option", "message_id",
  "content": "<текст, зашифрованный ключом чата как сообщение>"}` (до 4000
  символов шифротекста). Можно, если `open_add` или ты автор; не в закрытом и не
  в викторине; всего не больше 20 у опроса и 50 у чек-листа. Номер нового
  варианта = прежнее `options`.
* Состояние (`poll` в `new_msg`, истории, `poll_update`) — новые поля: `kind`,
  `close_at`, `hide_results`, `open_add`, `extra: [{"i", "by", "content"}]`
  (расшифровать `content` ключом чата → текст варианта `i`), и `hidden: true`,
  пока итоги скрыты (тогда `counts` нули, `voters_by_option` нет, `voters` и свой
  `my` — есть). `options` растёт с добавлением.
* Показ опроса: в строке вида «· итоги после завершения», «· до 19 окт., 21:29»;
  проголосовавшему при скрытых итогах — «1 голос · ваш голос учтён», варианты не
  нажимаются, «Отменить голос» есть; «+ Свой вариант» → поле ввода, Enter
  добавляет.
* Окно создания: переключатель «Опрос / Чек-лист»; у опроса новые галочки
  «Участники могут добавлять свои варианты», «Итоги - только после
  завершения» и «Завершить сам: нет / через час / сутки / 3 дня / неделю»; у
  чек-листа — только «Участники могут добавлять пункты».

### Закрепы в группах и в группах с темами (с 2026-10-21)

Полный порядок для групп (у Android закрепы в группах не работали):

* **Закрепить / открепить:** WS `{"action":"pin_msg","message_id":N}` /
  `{"action":"unpin_msg","message_id":N}`. В группе разрешено ролям
  `owner, admin, editor, helper`; остальным сервер отвечает
  `{"action":"error","message":"Закреплять сообщения в группе могут только администраторы."}`
  (пункт «Закрепить» им лучше не показывать — роль есть в `my_role` списка
  чатов). В личке — любому из двоих.
* **Событие всем участникам группы** (и автору): `{"action":"msg_pinned"|"msg_unpinned",
  "id", "sender" (автор сообщения), "receiver" ("group_N"), "pinned_by" (кто
  закрепил), "content" (шифр, как у сообщения), "file_type", "topic_id",
  "pin_event": {"id","after_id"}}` (`pin_event` — только у `msg_pinned`).
  **Чат события:** если `receiver` начинается с `group_` — это `receiver`; в личке —
  тот из `sender/receiver`, кто не ты. Сравнивать с открытым чатом по `sender`
  в группе нельзя — событие не найдёт свой чат.
* **При открытии чата:** `GET /api/messages/{me}/{chat}/pinned` → `{messages:[{id,sender,
  content,file_url,file_type,created_at,topic_id}]}` — полоса закреплённых;
  `GET /api/messages/{me}/{chat}/pin_events` → `{events:[{id,message_id,actor,after_id,
  created_at,sender,content,file_type,topic_id}]}` — строки «Имя закрепил(а) «текст»»
  в ленте после сообщения `after_id`. `content` расшифровывать ключом чата (в группе —
  ключом группы, с откатом на старый ключ из номера).
* **Темы (форум):** закреп показывается **только в своей теме**. Оба запроса принимают
  `?topic_id=` — номер открытой темы, `0` — «Общее» (как у истории). На `msg_pinned`/
  `msg_unpinned` с `topic_id` другой темы (пусто = «Общее» = 0) в открытой теме ничего
  не делать — ни полосы, ни строки «закрепил(а)». Без `topic_id` (группа без тем) — все
  закрепы группы, как раньше.

## WebSocket

Адрес: `wss://<домен>/ws/{username}/{device_id}`

`device_id` — постоянный идентификатор установки, генерируется один раз
и сохраняется.

**Токен передаётся субпротоколом**, а не в адресе:
заголовок `Sec-WebSocket-Protocol: bearer, <jwt>`.
В OkHttp это делается добавлением заголовка при создании запроса.
Сервер подтвердит субпротокол `bearer`.
Приём токена из query-строки на сервере остался, но использовать его нельзя:
адрес попадает в логи прокси открытым текстом.

Отказ по токену (нет токена, подпись не сходится или срок истёк, токен выдан
другому имени, версия устарела после смены пароля или «завершить сеансы»).
С 2026-09-16 соединение сначала **принимается**, приходит сообщение
`{"type":"session_terminated","action":"force_logout","reason":"expired"|"revoked"}`,
затем закрытие с кодом `4003`. Раньше закрывалось до рукопожатия (HTTP 403).
Обработка: очистить сохранённые данные и показать экран входа — не
переподключаться.

### Отправка на сервер

```json
{"action":"send","receiver":"...","content":"<зашифровано>","file_url":null,
 "file_type":null,"reply_to":null,"forwarded_from":null}
{"action":"typing","receiver":"..."}
{"action":"stop_typing","receiver":"..."}
{"action":"read","message_id":123,"sender":"..."}
{"action":"reaction","message_id":123,"emoji":"👍"}
{"action":"edit_msg","message_id":123,"content":"<зашифровано>","receiver":"..."}
{"action":"delete_msg","message_id":123,"mode":"both"}
{"action":"pin_msg","message_id":123}
{"action":"unpin_msg","message_id":123}
{"action":"rtc_signaling","receiver":"<только пользователь>","data":{...}}
{"action":"schedule", ...как send..., "send_at":"ISO-8601 с поясом"}
{"action":"set_timer","chat":"<собеседник|group_N>","seconds":0|86400|604800|2592000}
{"action":"poll_vote","message_id":123,"options":[0]}
{"action":"poll_close","message_id":123}
{"action":"gcall_join"|"gcall_leave","chat_id":"group_N"}
{"action":"gcall_signal","chat_id":"group_N","target":"<участник>","data":{...}}
{"action":"ping"}
```

`receiver` — имя пользователя либо `group_<id>`.
`message_id` — число (строка из цифр тоже принимается).
У `send` необязательное `"silent": true` — сообщение без звука и без push.
Предел частоты: 40 кадров `send`/`edit_msg`/`schedule`/`poll_vote` за 10 секунд.
`content` — не больше 32 КБ (клиент режет текст на 4096 символов). Кадр
целиком — не больше 128 КБ, иначе `error`.
`reply_to` на сообщение из другого чата сервер обнуляет.
`typing`, `send` в чужую группу и `rtc_signaling` в группу молча отбрасываются.
`ping` раз в 25 секунд — сервер отвечает `{"action":"pong"}`.
`mode` при удалении: `both` (у всех, только своё сообщение) или `me` (только у себя).

### Приём от сервера

```json
{"action":"new_msg","id":..,"sender":..,"receiver":..,"content":"<зашифровано>",
 "file_url":..,"file_type":..,"status":"sent","reactions":"{}","is_edited":false,
 "reply_to":..,"reply_to_sender":..,"reply_to_content":"<зашифровано>",
 "is_pinned":false,"forwarded_from":..,"created_at":"ISO-8601"}
{"action":"msg_read","id":..,"up_to":..,"receiver":..,"reader":..}  // up_to (с 2026-10-07): прочитано всё своё в этом чате с id <= up_to
{"action":"msg_edited","id":..,"content":"<зашифровано>","receiver":..}
{"action":"msg_deleted","id":..,"receiver":..}
{"action":"reaction_update","message_id":..,"reactions":"<JSON-строка>","receiver":..}
{"action":"msg_pinned"|"msg_unpinned","id":..,"sender":..,"content":..,"file_type":..}
{"action":"presence","username":..,"online":true|false}
{"action":"typing"|"stop_typing","sender":..,"receiver":..}
{"action":"rtc_signaling","sender":..,"data":{...}}
{"action":"error","message":".."}
{"action":"pong"}
{"action":"force_logout"}
{"action":"blocked","blocked_until":"ISO"|null}
{"action":"chat_timer","chat":..,"seconds":..,"set_by":..}
{"action":"scheduled_saved","id":..,"receiver":..,"send_at":..}
{"action":"scheduled_sent","id":..,"receiver":..}
{"action":"scheduled_failed","id":..,"receiver":..,"message":..}
{"action":"poll_update","message_id":..,"receiver":..,"poll":{...},"my":[..]?}
{"action":"group_settings","group_id":"group_N"}
{"action":"group_added"|"group_kicked"|"group_deleted","group_id":"group_N"}
{"action":"chat_cleared","target":..}
{"action":"profile_update","username":..,"avatar_url":..,"bio":..,"display_name":..,"status":..}
{"action":"gcall_peers"|"gcall_peer_joined"|"gcall_peer_left"|"gcall_state"|"gcall_full"|"gcall_signal", ...}
{"type":"admin_user_renamed","old_username":..,"new_username":..,"new_token":..}
{"type":"admin_user_deleted"}
{"type":"admin_password_changed"}
{"type":"contact_renamed","old_username":..,"new_username":..}
{"action":"story_new","author":..,"id":..}
{"action":"story_deleted","author":..,"id":..}
{"action":"story_viewed","id":..,"viewer":..}
{"action":"story_liked","id":..,"viewer":..,"liked":true|false}
{"action":"story_comment","story_id":..,"id":..,"author":..,"story_author":..}
{"action":"story_comment_deleted","story_id":..,"id":..}
```

`story_new` и `story_deleted` — повод перечитать `GET /api/stories`;
`story_viewed` и `story_liked` приходят только автору; `story_comment*` — всем, у
кого есть ключ истории (и самому комментатору: не прибавляйте счётчик дважды).

У `new_msg` есть также `expires_at` (ISO с `Z` или `null` — когда сообщение
удалится по таймеру чата; сервер сам пришлёт `msg_deleted`), `silent` и `poll`.
`msg_pinned` содержит `pinned_by` — кто закрепил, и `pin_event`
`{id, after_id}` — ту же пометку, что потом вернёт `pin_events` (по `id`
не задваивайте её при перечитывании ленты).

`reactions` — JSON-строка вида `{"имя_пользователя":"эмодзи"}`.У одного
человека не больше одной реакции на сообщение: повторное нажатие на тот же
эмодзи удаляет ключ пользователя целиком, нажатие на другой — заменяет значение.

В группах событие `typing` приходит и самому отправителю: рассылка идёт по всем
участникам. Отбрасывайте события, где `sender` — вы сами.

Соединение нужно восстанавливать при обрыве и при возвращении приложения
из фона, с нарастающей задержкой между попытками.

## Звонки

WebRTC, сигнализация через `rtc_signaling` в том же сокете. Серверы для
соединения брать из `GET /api/turn-credentials` → `{iceServers:[...]}` —
там свой TURN (UDP/TCP 3478 и TLS 5349) с временными учётными данными.
Итог звонка записывает вызывающий: `POST /api/calls/log` `{peer, status,
duration, video}`, `status` — `answered|missed|declined|busy|failed`.
История: `GET /api/calls` → `{calls:[{id, peer, peer_name, avatar_url, outgoing,
status, duration, video, time}]}`.

Групповые звонки — сетка «каждый с каждым» до 5 участников, сигнализация через
`gcall_*` (см. WebSocket).

Заблокированный модератором аккаунт звонить не может: `rtc_signaling` от него
отбрасывается молча, а `gcall_join` получает `error`. То же при личной
блокировке собеседником.

«Кто может мне звонить» (`call_privacy`, с 2026-09-29): если настройка
адресата не пускает звонящего, `call_invite` и `offer` вне принятого звонка до
него не доходят (и push тоже), а звонящий получает
`{"action":"rtc_signaling","sender":"<адресат>","data":{"type":"call_denied"}}` —
завершите звонок с сообщением «Этот человек не принимает звонки от вас».
Остальные сигналы (ответы, `candidate`, `hangup`) настройкой не проверяются:
человек с `nobody` может звонить сам. Повторное `offer` (камера, показ экрана)
внутри звонка проходит, если на приглашение ответили `call_accepted`.

## Подводные камни

**Один пользователь, несколько устройств.** Приватный ключ выводится из пароля,
поэтому на каждом устройстве он получается одинаковым. Отдельной синхронизации
не требуется. При смене пароля меняется `token_version`, и все старые сессии
принудительно закрываются.

**Ключ переписки кешировать в памяти.** Вывод ECDH на каждое сообщение
заметно тормозит длинные чаты.

**Расшифрованные вложения тоже кешировать**, иначе прокрутка ленты будет
перерасшифровывать одни и те же файлы.

**Сообщение может не расшифроваться** — например, собеседник сменил пароль
и перевыпустил ключи. Показывать заглушку, а не падать.

**HTML-сущности.** Веб-клиент местами прогоняет содержимое через
преобразование сущностей; в тексте могут встретиться `&quot;` вместо кавычки.
При разборе учитывать.

**Удалённый аккаунт.** Приходит со `status: "deleted"`. Переписка с ним
остаётся и читается: публичный ключ сохраняется именно для этого, не
удаляйте его у себя. Писать ему нельзя - сокет ответит
`{"action":"error","message":"Этот аккаунт удалён - написать ему нельзя."}`.
Показывайте «Аккаунт удалён» вместо «не в сети» и прячьте звонки.

**Пустые сообщения сервер не принимает.** Сообщение без текста, вложения и
опроса отбрасывается молча. Вложение считается содержимым - подпись не
обязательна.

**Новый аккаунт сразу получает письмо от поддержки** (отправитель
`support`, `file_type: "system"`): первая строка - заголовок, остальное -
текст. Показывайте его как есть, расшифровывать не нужно.

**Отчёт об ошибке (необязательно).** `POST /api/client-error` без
авторизации принимает `{message, source, line, column, stack, page}` и
отвечает 204. Присылайте скупо и никогда - содержимое переписки.

**Сертификат.** Пока домен не настроен, сервер работает по IP с
самоподписанным сертификатом. Android его отвергнет — тестировать
на настоящем сертификате либо временно добавлять исключение
через network security config **только в отладочной сборке**.

## Что должно быть в приложении

Обязательный минимум:

1. Регистрация и вход, с полной схемой ключей
2. Список чатов: личные, группы, папки, счётчики непрочитанного, статусы онлайн
3. Переписка: отправка и приём в реальном времени, история с подгрузкой вверх,
   ответы, редактирование, удаление, пересылка, реакции, закрепление
4. Вложения: изображения, документы, голосовые, видеосообщения — со сквозным
   шифрованием по описанной схеме
5. Группы: создание, участники, роли, приглашения по ссылке, публичные группы
6. Профиль: аватар, отображаемое имя, описание, приватность
7. Push-уведомления о новых сообщениях
8. Хранение токена и KEK в защищённом хранилище

Желательно: звонки, тёмная и светлая темы, поиск по сообщениям,
работа в офлайне с локальным кешем.

## Требования к качеству

- Ключи и токены — только в EncryptedSharedPreferences или Keystore,
  никогда в обычных настройках и не в логах
- Ничего секретного не писать в logcat даже в отладочной сборке
- Ошибки сети и расшифровки обрабатывать, а не глотать
- Тесты на криптографию обязательны: зашифровать в приложении — расшифровать
  тем же алгоритмом, что и в вебе, и наоборот. Это единственный способ
  убедиться в совместимости до релиза
